# v0.3.0-beta3：自动搜索路由与更顺畅的社区接入

版本：**0.3.0-beta3**；开发分支 **`v0.3.0`**，Git 标签 **`v0.3.0-beta3`**，npm 通道 **`beta`**。不合并到 `master`，不移动 npm `latest`。源码、标签和发布说明不证明 npm 发布成功，请查询 registry。

## 安装与更新

```bash
npm install -g search-boost@beta
# 固定本次版本：
npm install -g search-boost@0.3.0-beta3
search-boost tui
```

已有 Agent 接入须按其安装方式刷新并重启 / 重连；运行中的 MCP、Pi 或 DSH 适配器不会自动加载新代码。无参数 `search-boost` 保留快速配置向导。

## 相比 beta2 的变化

### 搜索引擎：一个 API 即可，默认自动选择

整合 [PR #37](https://github.com/Mr-remon219/search-boost/pull/37)：

- 新增 **`deepseek-search`**：通过 DeepSeek 原生 `web_search_20250305` 返回结构化来源和引用摘录，支持 API Key、独立 Base URL、启停与融合权重。三个排序预设从中性权重 1.0 起步，不承诺质量或来源独立性。
- 默认请求只要存在已配置且启用的 API，就使用启用的 API；否则使用免 Key 引擎。无需选择搜索层，也不要求配齐所有供应商 Key。
- 快速配置与完整控制台均支持单引擎启停、**只用这个 API**、保存 Key 后的实际启用状态提示。保存 Key 不自动扩张已有白名单，不删除其他 Key 或自定义地址。
- 默认自动选择不再为未配置的供应商刷无关警告；显式指定引擎或引擎池时仍报告不可用状态。

**费用与兼容性：**已有 Key 且已启用的 API 会进入默认搜索，可能计费；每个 DeepSeek 查询变体可能产生一次模型和搜索费用。需要免 Key 搜索时显式指定 `engine_pool: "free"`。API 请求失败不静默切换免费池；显式 `free / api / hybrid`、旧的单次请求 layer 别名、检索档位和排序语义保留。持久化的旧 layer 偏好不再控制默认自动选择。见 [DeepSeek 接入](deepseek-search.md)与[搜索路由](search-routing.md)。

### 社区接入：选平台、扫码，之后复用

整合 [PR #38](https://github.com/Mr-remon219/search-boost/pull/38)：

- 小红书、知乎、B站各提供一个内置免费接入，不要求另行部署 MCP 服务；旧配置仍可读取。
- 浏览器可明确选择本机程序或 SearchBoost 独立下载。只复用浏览器程序，**不导入个人 profile、Cookie 或扩展**；下载有明确来源选择，卸载仍需确认。
- 已配置浏览器和平台会话直接复用；暂停后恢复不强制重新扫码。首次引导把社区连接放到最后，允许空选跳过，不逐平台重复确认。
- 后台隔离浏览器取得二维码，验证真实账号身份后自动保存。快速配置和控制台支持 **O 打开 PNG、R 重发、Esc 返回**，提供准备 / 下载 / 等待 / 保存进度和就地重试。
- 平台启停、恢复与 Reddit 范围编辑直接保存；删除登录 / 浏览器保留默认取消的确认。dry-run 不下载、不登录、不写配置。
- 同平台并发检索短暂、可取消地等待会话；只合并无关平台的配置变更，同平台冲突仍拒绝覆盖。限流或一般访问限制不误导用户重新登录，也不自动开启宿主工具权限。
- 修复控制台按 Q 后终端恢复但进程不退出的问题。两套 TUI 共用状态与恢复文案。

详见[浏览器与扫码登录](community-browser-login.md)及[17 项 UX 问题与修复记录](community-ux-audit.md)。

## 整合后的额外修正

1. 合并自动路由和社区引导，保留单次只读自动选择说明，不再等待已移除的搜索层菜单；保留最后的可选社区连接和引擎保存反馈。
2. 对照锁定的 `playwright-core@1.64.0` 源码，修正真实目录名 `chromium_headless_shell-<revision>` 的卸载识别。旧 fixture 错用连字符，无法发现真实下载后的卸载失败；现在用真实形状复现并回归，保留未知目录和共享缓存保护。
3. 浏览器所有权标记改为在共享 setup 锁内核验 / 创建，避免与并发卸载交错后留下无主下载目录。
4. 平台断开时复用已死 PID 的安全恢复规则；活进程、空白 / 损坏锁和不明路径继续拒绝删除，不因等待过久强行解锁。
5. 新二维码尝试在平台会话锁内清理上次异常退出遗留的自有 UUID PNG，不触碰其他平台或不明文件。正常退出立即清理；强制终止或断电无法保证即时执行清理，界面和文档已明确这一限制。

## 验证与限制

发布检查包含 `npm run check`、`npm run check:ci`、`npm run audit:dependencies` 与 `npm run test:isolation`。本版本有 **331 个语法检查文件、103 个隔离回归入口**；入口覆盖两套 TUI、自动路由、DeepSeek 模拟协议、浏览器生命周期、二维码、讨论完整性、宿主适配与包内容。隔离门禁同时检查模拟用户文件和源码树未被测试改写。

本地额外验证：Linux 真实 PTY 在 80×32 和 120×32 下显示控制台并按 Q 正常退出，使用隔离环境且不带真实凭据。新反例先复现真实形状的卸载失败、死锁残留断开失败和崩溃二维码残留，再验证修正。

独立审查子任务返回了具体线索，但因所请求的 `x_search` 不在子任务工具列表内而被标记 failed，**不作为成功的独立审查门禁**。上述问题由父任务直接核实源码、复现和回归。发布须以最终提交的本地检查与跨平台 CI 结果为准；registry 连接失败不算“审计 0 漏洞”。

未使用真实 API Key 调用 DeepSeek，未下载真实 Chromium，未用真实账号验收三平台扫码、挑战或登录后检索；Windows / macOS 原生终端点击与浏览器发现仍需真实环境验收。离线测试和 CI 不证明在线可用性、费用、检索质量、穷尽覆盖或宿主已加载新版本。

## English summary

Beta3 integrates PRs #37 and #38: native DeepSeek search, automatic enabled-API selection, single-API configuration, reusable isolated community browsers, verified QR login, progress/retry controls and clean terminal exit. Additional fixes cover Playwright's actual underscore directory names, ownership under the setup lock, provably-dead session locks and stale private QR images. Existing enabled APIs may incur charges; request `engine_pool: "free"` for keyless search. API failures never silently change pools. Install `search-boost@beta` or pin `0.3.0-beta3`; stable `latest` and `master` remain unchanged. No live provider, browser-download or authenticated-platform acceptance is claimed.
