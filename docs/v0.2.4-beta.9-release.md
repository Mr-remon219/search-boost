# v0.2.4-beta.9：Desktop 接入兼容与损坏配置导航修复

仅发布 npm beta，稳定 latest 保持 0.2.3。基于拉取的 origin/v0.2.4（122edad，含 f8d4327 和 beta.8 合并），经审查修正后交付。

## 本次改动

- Windows Desktop 自动发现增加官方安装器卸载注册表元数据，覆盖自定义盘符、中文及空格目录。只读固定脚本、失败后继续默认目录/PATH，不执行注册表命令字符串。保留显式 launcher 覆盖的权威性。
- 登记目录限定为本地盘符绝对路径，要求同级应用可执行文件存在；支持字面百分号，拒绝未解析的变量。原始查询结果缓存 10 秒（含不可用结果），变量和文件存在性不缓存，避免热路径反复启动 PowerShell。现有 Windows shell 元字符限制不放宽。
- 交互安装可明确选择 Desktop 本地目录接入，即使自动发现失败也可选择 Desktop。路径和说明放在其他接入（含 Grok）结束后的最后阶段，由用户在官方 Desktop「插件 → 添加插件」安装当前持久目录；不是通过 npm 另装 DSH。
- SearchBoost 仅只读观察保存的来源、版本、载荷、启用状态及稳定记录。有 launcher 时校验所属运行时的实际解析来源；没有 launcher 时明确只验证磁盘安装，不声称实际加载。禁用状态保留，显式启用请求由用户在 Desktop 完成。临时 npx 目录拒绝作为持久链接。
- 手动等待可 Esc / Ctrl+C 取消，并恢复终端和监听器；保留之前完成的接入。已知运行时验证失败不降级为成功：同一指纹最多 3 次失败探针及封顶退避，仍失败提前报告未完成，不循环派发数百次。dry-run 不等待、不派发、不修改 profile。
- Grok 原生插件交互核验放在其他刷新任务结束后，避免重建信任确认框与并行输出交错。Grok MCP/原生插件分开标识，DSH 默认输出简洁的真实完成状态，详细耗时与派发保留在 last-refresh.json，refresh --verbose 可查看。migrate 不接受并忽略这个刷新专用参数。
- 修复用户报告的 P2：损坏 keys.json 使默认平铺首页在任何菜单调用前退出。只为显示提示捕获配置读取失败并显示「配置错误」，平铺/文件夹、中英菜单仍可操作、正常退出。实际密钥/搜索层读取与配置继续严格报错，损坏或不可读存储不被替换成空配置或自动覆盖，健康配置不变。

## 验证与审查

新增/扩展隔离回归覆盖注册表解析与查询缓存、完整/缺失 Desktop 应用、双语接入与顺序、稳定读与真实探针子进程（Node 模拟 carrier）、来源/载荷不符、禁用、重试/取消/超时/dry-run，以及坏密钥提示与严格操作边界。

已记录红绿证据：坏密钥首页 select 次数 0 vs 预期 1；失败探针 50 次 vs 预期 3；字面百分号目录丢失；migrate --verbose 未拒绝。独立只读审查提出具体发现，父进程逐条核实、修复和验证；没有采用将已知运行时失败静默降级为成功的建议。

发布要求最终完整 prepublishOnly（语法、CI 策略、依赖锁审计、所有有毒调用者隔离入口）、准确最终提交的四格 CI（Linux Node22.13 / Windows22 / macOS22 / Linux24），以及实际 npm tarball 与该提交逐文件核验。只在 CI 全部成功后发布已验收 tarball 到 beta。registry 处理期仅只读核查，不重复发布。

GUI 真实加载、用户具体 Desktop 版本/安装路径、真实 Windows 注册表形态、Electron/ASAR 和付费服务未在本次本地测试中验证；对应平台 CI 不代替真实 GUI 会话。官方 master 文档确认本地目录入口，但不证明用户已经下载的版本具有相同接口。未操作真实宿主配置、缓存、全局安装、信任或凭据。

## 更新与回退

```sh
npm install -g search-boost@beta --prefer-online
search-boost
# 管理 Agent 接入 → 刷新已有接入 → 选择精确范围
```

仅官方 Desktop 用户不必额外安装 npm DSH；需要新接入时在管理页选择安装、DSH、Desktop，再选择自动或本地方式。自动方式先启动一次初始化，再完全退出（含托盘）；本地方式保持 Desktop 运行，由用户审核宿主的安装/信任提示。启用及重启按宿主提示完成。refresh 保留现有权限/禁用状态，不自动升级宿主，普通 -y 不授权 Grok 缓存重建。

需要回退时，保留配置和事务备份，显式安装 search-boost@0.2.4-beta.8，按该版管理入口及 dry-run 审核后刷新已有接入。手动本地链接依赖来源目录持续存在；不要删除 profile/数据、绕过信任确认或移动稳定 latest 来伪造恢复。
