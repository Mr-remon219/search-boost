## 已发现并修复的设计问题

| 环节 | 原有逻辑问题与反例 | 修复 |
|---|---|---|
| 缺口生命周期 | 终检要求补点 B，但点 A 新增合格材料会改变全局签名，使 B 被视为已满足，并对同一 B 材料反复终检。反例出现3次终检，预期1次。 | 缺口持续存在，只有有效整体终检才能关闭/转移；只有 B 自己的当前研究材料变化才触发重审。 |
| 新材料与重复结果 | 同摘录、标题、日期和类型的镜像 URL 虽没有新增信息，也能消耗终检额度；数字评分抖动同理。 | 缺口变化键按研究内容/元数据去重，与严格的 scope/质量版本键分离。新 URL 仍保留在结果中，安全准入仍逐 URL 重新核验。 |
| 终检材料选择 | 多份高分正向材料挤掉已准入但略低分的反证；终检被要求检查矛盾，却没看到反方材料。 | 保留最强材料、已知反证/相对视角、新缺口材料，再用去重组差异填充剩余空间；必要视角放不下则诚实停止，而非删掉反证后 finish。 |
| 停止判断的量纲 | 高 confidence 可覆盖 P(finish)=0.51，甚至覆盖与所选项矛盾的概率向量；可选字段是否存在改变了停止规则。 | 前筛与终检复用完整、有效、选项一致的分布校验。finish 只按 P(finish)≥0.85，不混用 confidence。 |
| 继续判断的粒度 | 两个同样值得继续的点各获0.495，finish仅0.01；要求单点概率≥0.85会误入 pending，反复重问而不搜索。 | 先判断继续这一动作族的概率 1−P(finish)，再按有效 Choice 选择最受支持的点。增加搜索点不应仅因概率分摊而阻塞继续。 |
| 轮次资源分配 | 点 A 的100个候选可以消耗12次判断预算，点 B 连一次定向搜索都没得到。只有全局硬预算，不足以保证流程公平。 | 每研究轮至多2个前筛/质量调度步骤；允许未关闭点继续检索，不先清空旧池。新材料在前筛和质量阶段都获优先机会。 |
| 研究输入到检索的传递 | constraints 只在过滤时使用；关键词和限制也未参与正文摘录。页面上已有平台限制或 rollback 段落，却被多个通用介绍段落挤掉。 | 完整限制加入可选自然语言查询，仍保留宽查询；不自动生成 AND/site/时间过滤。正文按问题、条件、关键词分配摘录机会；补读针对未知条件和当前缺口。intent 不进入引擎查询。 |
| 未知与否定 | 相关性等分数齐全但所有关键词回答缺失，材料被标成 off_topic，pending为0；已有一个点准入时，另一点的未知也被隐藏。 | 分开“已有准入依据”和“所有必要判断已完成”。未知仍 pending；只给有确定匹配的点记贡献，不撤掉其他点已有的有效准入。 |
| 引擎规划到续搜 | 首次仅保存被选引擎的权重，低分未选引擎在续搜时回到默认1，反而高于已选引擎的0.9。 | 保存全部被评估引擎的适合度；缺失答案使用中性排序值。权重不成为来源可信度，也不越过配置/健康限制。 |
| 无法终检时的退出 | 三次终检额度已用完后仍进入下一轮；无法容纳必要材料可能消耗空轮次；服务失败的实际终检未计数。 | 在下一次规划前检查终检额度；无法容纳必要视角明确预算停止；失败但已派发的终检计数，未派发的预约失败不计数。 |

## 公式审查：保留什么，为什么

### 1. 准入与排序不能互相替代

对固定的当前材料及判断，准入为：

```text
E_i = scope_eligible_i
      AND r_i > 0.60 AND v_i > 0.50
      AND d_i >= 0.65 AND injection_i <= 0.70
      AND 存在 k：m_ik > 0.50
```

必要值缺失不等于0分负例，也不通过准入。范围检查先于独立的质量请求；一个确定违反条件足以拒绝，未确定条件保持未知。增加一个条件，不会扩大合格集合，也不会降低相关性、方向或其他门槛。

各条件的0.85是未标定的模型判别阈值，不是全部条件共同正确的概率。不能把这些条件相乘来伪造联合置信度，也不能用加权平均抵消违反条件。

### 2. 单问题下 F 不是另一份独立证据

```text
u_i = min(r_i, v_i) × d_i
q_ik = u_i × m_ik
A_k = max_i q_ik
F_k = A_k                 // 当前入口没有额外 topics
S_k = 0.25A_k + 0.90F_k + 0.10R_k
    = 1.15A_k + 0.10R_k
```

`min(r,v)`防止相关性补偿低阅读价值；d在硬门控之后仍影响排序。各 Noul 数值高度相关，u、q都只是启发式效用，不是独立事件的联合概率。

按某点的去重组最强质量排序为 Q₁≥Q₂≥…≥Q_g，有：

```text
R_k = Σ(j=2..g) (1−ρ)ρ^(j−2) Q_j，ρ=0.5
0 ≤ R_k ≤ A_k(1−ρ^(g−1)) ≤ A_k
0 ≤ S_k ≤ [1.25−0.10ρ^(g−1)]A_k ≤ 1.25
```

因此 S 可以超过1；不能套用旧事实覆盖模式的“分数>1即就绪”。当前控制器以当前合格材料是否存在决定点就绪，再单独做整体终检。没有缺乏线上证据却重调0.25/0.90/0.10系数；本轮明确其退化关系、边界和不具备的含义，并将解释加入终检提示。

固定准入及去重组时，提高 r/v/d/m 不降低分数；同一组重复材料不增加R。组划分可能因新增近复制关系而合并，所以不承诺跨任意新增材料的计数单调性；撤销或变化也应允许降低计数。跨站不证明独立，同站保守归组也可能低估数量。

### 3. 停止与继续使用不同粒度、相同分布

- 分布必须完整、数值有效、总质量近似为1，并与返回选项一致。
- finish：所选为 finish 且 P(finish)≥0.85。
- 继续：所选为关键词且 1−P(finish)≥0.85；选择最受支持的关键词，不要求这个点独占0.85概率。
- 中间不明确区域保持 pending，有限重试。

这里合并的是同一封闭动作 Choice 的互斥选项，不是相加不同限制或文档的分数。选择继续不会增加任何材料的准入概率，更不会宣称该点已完成。

新增15项流程回归，当前 `scripts/test-single-target.mjs` 共56项；评分测试共14项，新增的代数测试覆盖243组 r/v/d/m/组数组合及固定集合内的单调性。反例先运行失败再修复，包括跨点缺口、反证遮蔽、概率量纲、旧池饥饿、摘录偏置、未知隐藏、镜像假进展和引擎权重丢失。

执行检查：

```sh
npm run test:retrieval
npm run prepublishOnly
git diff --check
```

这些是控制逻辑和代数验证，不证明在线语义准确率、低误拒率、真实性或实际延迟改善。每轮2步、0.85等仍是有限预算下的工程策略，需真实任务评估召回/成本；有限摘录、每点最多3份终检代表材料和保守分组仍可能漏掉重要信息。未识别为反证的材料不因此获得反证保留保证。终检返回的是值得阅读的一组材料，不是答案完整性认证。
