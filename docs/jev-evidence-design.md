# Jev 证据检索设计：广搜、事实覆盖与有界佐证

状态：**事实级控制器已落实到当前工作树；未发布，权重和真实质量仍待校准。**
本设计吸收 2026-09-27 的隔离实验，并以最后确认的“首条加分、多证据递减、新事实覆盖加分”修正累计规则。
当前实现契约仍见 [jev-adaptive-search.md](jev-adaptive-search.md)。

## 1. 三个版本不要混淆

| 层次 | 状态 |
| --- | --- |
| 当前仓库运行代码 | 已集成广池调度和本文事实级公式；含受预算约束的证据束判断 |
| V2 实验候选 | 已实现500候选、关键词指数、比例恢复、最终检查；保留为参考，未验证质量优于旧版 |
| 本文事实级公式 | 已替代全局文档序号递减；事实归属由typed判断取得，参数仅为工程起点 |

归档的 [V2补丁](design-assets/jev-v2/candidate.patch) **不是本文最新事实公式的实现**。不得因有补丁或回归通过而把设计标为已发布。

## 2. 执行流程

```text
目标问题＋关键词＋明确限制
 → 首轮广搜：全局最多500个去重URL
 → 分批判断：相关性、局部事实、注入/日期等
 → 合格证据关联到关键词及事实单元；不确定材料保留为线索
 → 更新基础分A、事实覆盖F、有界佐证R
 → 有关键词未就绪：先处理pending，再按剩余比例补搜
 → 全部关键词就绪：Jev检查实质遗漏与未解决矛盾
 → 通过则covered，否则有界补洞或诚实返回不足
```

- **入候选池不设Jev概率门**。引擎返回先去重收集，再判断能否进入合格证据集。
- 去掉额外引擎数量帽，不等于强制调用所有引擎，更不允许启用未配置/禁用/未授权付费引擎。
- 500是每轮全局候选URL上限，不是每个目标/引擎各500，也不是保证返回500条。
- 普通 `fused_search` 的公开上限不变；大池仅走内部候选接口。
- 同一来源可支持多个关键词，需分别判断。关键词按验收问题语义解释；同义词不应制造额外独立事实或强制多份来源。
- 循环轮数、请求、token、时间仍由代码/宿主限额控制，模型不能自行扩额。

## 3. 证据准入与状态

证据模型保留三层：`candidate_pool`（候选/线索）、合格局部证据集、用于最终判断的证据束。未知、待审、可疑和拒绝材料有明确状态与原因。

V2试验起点是关键词相关性 `r > 0.60` 且证据性 `e > 0.60`，分别过门，不合成一个概率。注入判断须有效且≤0.70；日期、版本等既有硬约束不可由高分抵消。

**0.60未被证明是最优阈值。** 0.58/0.60/0.62在开发样本上没有区分。保留局部材料与宣布任务完成是不同决策；最终检查曾用0.60，只是实验值，不据此确认生产放行门。

- 局部事实不需要单独完整回答复合问题。
- 有效反证可以回答问题，不能因否定前提而删除。
- `null`、无效或过期判断属于unknown，不是0，也不能赚确定的完成分。
- 事实归属不明、独立性不明时保留线索，不假装获得新增覆盖/独立佐证。

## 4. 去重：页面、内容、事实分开

1. **页面身份**：规范化URL，仅移除确定无语义的追踪字段/锚点。版本、地域等语义参数不得误删。重复发现同一页合并来源和新片段，不重复建证据。
2. **内容身份**：文本指纹/近重复检测用于发现转载和镜像，同源复制归组。保留来源记录，优先展示原始或更完整来源；新增段落不能因包含旧段落而整篇删除。
3. **事实身份**：记录事实ID、适用版本/时间/地域、立场、原文片段、来源组、文本版本。只有语义一致且条件一致的材料才是同一事实的佐证。

不同引擎不是不同来源；不同域名也不自动独立。同一站点的互补事实则应正常贡献新覆盖。文本不相似不等于新事实；翻译、改写和转载仍可能是同一内容。

## 5. 修正后的分数：基础分＋事实覆盖＋递减佐证

对关键词k，先固定其目标的验收事实单元 `f` 和正权重 `w_f`，满足 `Σw_f=1`。不能每搜到一个新措辞就增加事实数量或重置分母。任务范围确实改变时，应版本化事实集合并重算，而不是悄悄变更标准。

实现中事实覆盖按目标共享，关键词各自需要合格材料才能就绪；同义词不会复制事实单元。可在target提供1–8个`facts: [{id, question}]`；未提供时只按明确分隔符拆分验收问题，未能拆分的复合范围保留为一个单元，不宣称自动理解全部原子事实。

令 `q_d ∈ [0,1]` 为合格材料的质量特征（当前取相关性与证据性较小值），`a_df ∈ [0,1]` 为材料对事实f的支持/回答强度。二者均非校准正确率。

### 基础分：首条建立，后续只补差

```text
A_k(E) = max_{d∈E} q_d                 （空集为0）
```

第一条合格材料建立基础分；以后只有更强材料才提高A，不对每篇文章重复发首条奖励。用max而非到达顺序，避免检索完成顺序改变基础分。

### 事实覆盖：回到原来的集合覆盖公式

```text
F_k(E) = Σ_f w_f max_{d∈E} a_df
ΔF = F_k(E∪{d}) - F_k(E)
```

首次覆盖一个所需事实，或提高既有事实的支持强度，均按真实边际增益加分。
**第20条材料提供的新事实，不能因全局序号20而只拿1/20的分。**
当多个局部片段共同回答一个单元时，额外的有界`fact_bundle` typed请求判断联合支持；合格的证据束可作为F的候选，但不能冒充单条A或独立R。所有组成片段的版本、出处及最终检查可见性必须保留；缺少判断不自动累计成功。
同一材料含多个事实时逐事实计量，不以整篇文档反复发奖励。

### 额外佐证：同一事实内递减，且总奖励有界

对事实f，按独立来源组的支持强度排序；每组只保留最佳有效支持。`j=1`已由F计入，`j≥2`才贡献额外佐证：

```text
R_k(E) = Σ_f w_f Σ_{j=2}^{n_f} (1-ρ)ρ^(j-2) d_fj a_fj
0 < ρ < 1，0 ≤ d_fj ≤ 1
```

`d_fj`是有依据的来源独立性折扣，不是独立概率；转载/镜像不形成新独立组。`ρ=0.5`时第二、三、四个来源的权重为1/2、1/4、1/8。当前以此为工程起点，不称实验最佳。实现仅在明确首手证据判断>0.85时承认来源组具有佐证资格；该判断仍可能错，不是来源独立性的外部证明。
因为几何权重和≤1、`Σw_f=1`，所以 `R≤1`。不能堆几百篇同事实文章无限刷分。
反对立场必须保留并检查矛盾，但不能计作相互佐证。

### 总指数及边际贡献

```text
S_k(E) = α A_k(E) + β F_k(E) + γ R_k(E)
ΔS_k   = α ΔA_k + β ΔF_k + γ ΔR_k
```

- `α、β、γ ≥ 0`。当前工程起点为`α=.25, β=.90, γ=.10, ρ=.5`，满足下述代数约束，不照搬V2的tau，也不宣称已由真实质量实验校准。
- 若仍使用 `S>1`，系数必须允许充足证据越过1；不能把三者归一成总和1后仍要求严格大于1。
- 代码约束基础分与额外佐证不能单独买到完成，`α+γ<1`；同时验证单条高质量、完整材料能及时进入最终检查。
- 真正覆盖增益由F负责。R是有界的佐证奖励，不可冒充缺失事实的覆盖。
- 就绪还要求**没有已知缺失的验收事实**；否则即使S>1也不放行到最终检查，防止高基础分/佐证分掩盖第8个缺失事实。S只是指数，不是概率或搜索穷尽证明。矛盾和硬约束仍须在最终检查中处理。

例：首次解释“超时会取消任务”获得基础与该事实覆盖；另一独立来源重述只得递减佐证；原文转载十次不加分；首次解释“为什么实际耗时超过timeout”获得正常新增覆盖，不受全局篇数惩罚。

## 6. 后续检索配额与最终检查

沿用V2调度起点：

```text
U=0：停止补搜，进入最终检查
否则 B_next = min(500, max(24, ceil(500 × 1.25 × U/K)))
```

U/K为未就绪关键词比例；24防止最后一个困难关键词被饿死，1.25补偿剩余问题往往更难。它们是工程起点，不是实验确定的最优值。

- 先审查pending，再补候选；微批内按目标轮转避免排在后面的目标饥饿。直接围绕剩余关键词/事实缺口检索，不为凑轮数重复搜索。已全部就绪时可暂停排空，为最终检查留出预算并报告pending。
- Jev最终只检查实质遗漏、会改变答案的未解矛盾和明确限制。简短足够就及时放行，不强求穷尽背景或无必要的多源证明。
- 证据束每轮最多4次，按目标轮转；预留每个未完成目标至多一个最终请求的调用、HTTP重试和token空间，不提高硬预算。临时证据束网络失败只记警告，不重试同一快照；认证/限流/取消/硬预算等仍停止。
- 保留V2“初检＋至多一次修复复查”的有界模式。缺少判定不能自动放行；预算不足返回partial/unassessed及原因。
- 首轮全局500、批24、每轮至多64微批、全调用72次逻辑Jev/80次HTTP/1.2M估算token，仍作为当前硬帽。事实归属增加开销：新控制器500条单目标合成压力测试约33次逻辑请求、877879估算token；不能把它当作真实网页或多目标容量保证。
- 原文变更后撤销旧判断/旧贡献；重复轮数不加分。来源共享不得共享未经判断的目标结论。
- 输出保留每词A/F/R/S、ready、最终状态和pending数量；共享的missingFacts/factProgress只在每个目标的首个关键词记录一次，taskId/canonicalId用于区分跨任务同名目标。全部approved仍分页返回，不被六条诊断预览截断。适配器schema须一起修改。

## 8. 实现边界与后续验收

1. 事实ID来自固定验收单元，证据到事实映射与立场由typed判断取得并绑定文本版本。Jev只做其支持的typed判断；不要把自由文本生成或字符串差异当作已实现的事实识别。
2. 没有可靠事实映射时保留unknown，不用词数、段数或域名数量伪造ΔF。由同一未验证Jev判断同时充当算法特征与gold是不合格评测。
3. 将“同事实独立佐证”“转载/镜像/改写”“同站互补事实”“较晚出现的新事实”“反证”“版本差异”列为独立验收类型。
4. 比较V2与事实级候选，分开衡量局部保留、ready误触发、最终假完成、覆盖、延迟和实际HTTP/token开销。
5. 新验证数据执行前冻结；已揭盲样例只能回归，不反复调参后继续叫holdout。
6. 已恢复最终覆盖门>0.85，不采用V2的0.60。明确缺口和未知缺口判定独立否决放行。保留证据与最终完成的门仍需分别校准。

必须验证的不变量：重复材料不增分；新事实不受全局篇数惩罚；佐证总奖励有界；相反立场不互相佐证；到达顺序不应决定结果；文本变更撤销旧分；unknown不赚确定分；S过线仍不能绕过最终检查。

## 10. 当前验证与局限

见 [实现验证记录](jev-fact-implementation.md)。来源分组只给R折扣：相同站点/精确文本必合并，近重复用有界MinHash候选及对称shingle相似度，不能保证识别所有翻译/改写。未知来源不因域名不同就获得R；公共后缀近似可能保守合并不同作者。

最终检查保留每个事实的最强支持与反对见证；若文本预算不能容纳全部必要见证，不宣布covered。内部证据束也必须展开到真实片段，不引入虚构URL。
