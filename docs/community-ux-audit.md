# Community Search 用户流程体验审计与统一修复

## 范围与方法

目标：选平台、连接一次，此后直接搜索；普通操作少确认，等待有反馈，失败可就地恢复。保留下载的明确授权，以及删除会话 / 浏览器的确认，不自动登录、安装或提升工具权限。

先盘点，后统一修复。本清单在修改生产代码前冻结。走查包括真实菜单派发、隔离配置写入、控制台渲染 / 按键，以及模拟扫码和检索失败；不使用真实账号，不下载真实浏览器，不把模拟结果当作线上登录验收。

已观察的基线：

- 首次连接三个平台：1 次是否安装确认 + 1 次平台多选 + 1 次浏览器选择 + 3 次逐平台确认，合计 **6 次终端交互**（不含手机扫码）。
- 该模拟成功路径打印 15 条说明 / 结果消息，约 1054 个字符（路径长度随环境变化）。
- 已选定浏览器后重新登录，仍要选择来源并确认一次。
- 保留会话、未启用原生接入时，控制台首项是重新登录，并同时出现启用 / 停用，容易做错操作。
- Windows 扫描有 8 个串行系统查询，每个上限 3 秒，没有整体时间预算；24 秒是代码推导上界，不是实际 Windows 测量。

## 初步冻结问题清单：16 项

| ID | 问题 | 统一修复验收标准 |
|---|---|---|
| UX01 | 平台多选后仍逐个平台重复确认扫码 | 选择平台后连续扫码，无逐平台确认；空选即跳过 |
| UX02 | 已保存浏览器仍重复选择，多个本机浏览器还多一层菜单且不定位当前项 | 正常连接复用可用浏览器；更换来源放在浏览器设置，一层菜单定位当前程序 |
| UX03 | 启停、启用已保存会话、编辑 Reddit 范围还要预览和二次确认 | 普通操作直接保存并短提示；删除仍确认，dry-run 仍不写入 |
| UX04 | 快速配置与控制台状态不一致，暂停 / 未连接混淆，默认操作引导重新登录 | 共用平台状态：未连接、已配置、已暂停、需登录、浏览器待修复；优先恢复而非重新扫码 |
| UX05 | 首屏堆叠实现名、免责声明和重复隔离说明，重要操作被挤走 | 正常页只留状态、主要操作和一句提示；详细边界按需查看 |
| UX06 | 浏览 / 启动时同步系统扫描可能长时间无响应 | 默认只读展示不执行外部扫描；显式发现有反馈，系统查询有整体时间预算 |
| UX07 | 全局浏览器下载、打开登录页 / 生成二维码阶段缺少及时进度 | 操作开始立即显示准备 / 下载 / 获取二维码 / 等待扫码 / 保存阶段 |
| UX08 | 二维码显示前重复验证身份，之后高频开账号 API 页面 | 新会话先出二维码；已有身份检查有短超时，后续有节制验证，不以 Cookie 存在代替成功 |
| UX09 | 快速配置等待时只有 Ctrl+C，终端链接不支持时打开 / 重发 / 取消不方便 | 等待扫码支持 O 打开、R 重发、Esc 返回，结束后恢复终端与监听器 |
| UX10 | 二维码刷新 / 超时的反馈与等待倒计时不清楚 | 倒计时称为等待时间而不是承诺二维码有效期；就地一键重发，无重复来源选择 / 授权 |
| UX11 | 登录失败后只返回原菜单或泛化错误，重试要重走流程且留下失败退出码 | 失败有短原因和就地重试 / 返回；重试成功不留下失败状态 |
| UX12 | 浏览器缺失、会话忙、登录过期、限流都容易变成 retrieval_failed | 安全地保留错误类型并给出对应下一步，不回显原始错误 / 凭据 |
| UX13 | 扫码期间其他平台配置变化也使本次启用失败 | 合并无关平台变更；当前平台的冲突仍拒绝覆盖 |
| UX14 | 同平台并发搜索立刻争抢 profile 锁，用户误以为要重新配置 | 搜索短暂、可取消地等待；持续占用报告稍后重试，未知锁不强拆 |
| UX15 | 已配置平台再次进入首次引导仍重做登录，缺少清晰完成结果 | 跳过已配置项，给出连接 / 跳过 / 未完成摘要和直接使用提示 |
| UX16 | 工具入口关闭或真实登录失效时，“配置完成”没有准确恢复指引 | 工具关闭明确指向工具开关而不自动提权；检索失败保留已取结果，只有明确登录证据才建议重登 |

### 真实终端复测补记

**UX17：按 Q 后控制台恢复画面但进程不退出。** 真实 PTY 复现：备用屏幕已关闭，0.3 秒后进程仍活着。原因是 stdin 初始 `readableFlowing=null`，退出时被误当作原本就在流动，残留读取保持进程存活。验收：恢复原来的非流动态，真实终端按 Q 后正常退出，不只检查内存中的 Promise 完成。

本轮最终累计 **17 项**。新增项在真实终端复测发现后补入，不将初步清单当作覆盖所有缺陷的证明。

## 不改变的边界

- 搜索自身不弹确认、不自动下载 / 登录 / 改配置。
- 不因限流或一般访问限制就把账号判为过期，不自动切换旧接口。
- 不绕过验证码、网络代理、重定向和文件所有权策略。
- 非 Community 功能不借本轮改动大规模改写。

## 修复记录与验证

### 修复后对照

| 项目 | 修复前 | 修复后 |
|---|---|---|
| 有可用浏览器，首次连接三平台 | 6 次终端交互 | **1 次平台多选**，随后连续扫码 |
| 没有可用浏览器 | 多层来源选择、逐平台确认 | **平台多选 + 一次来源选择**；下载选项明确标注联网 |
| 已选浏览器后重登 | 来源选择 + 确认 | **0 次额外终端问答**，直接准备扫码 |
| 模拟首次成功路径文字 | 约 1054 字符 | **448 字符**；19 条阶段 / 结果记录，包含新增及时进度，不能等同于静态屏幕行数 |
| 普通启停 / 范围编辑 | 再次预览确认 | 直接保存，删除保留确认 |
| 系统发现预算 | Windows 理论上界 24 秒 | 默认整体 1.2 秒，单查询不超过 400ms；普通展示不发外部查询 |
| 控制台 Q 退出 | 画面恢复，进程可能挂住 | 恢复非流动输入，真实 PTY 正常退出 |

数字来自隔离模拟，路径长度和提示阶段会影响文字量；平台 App 的扫码 / 确认不计入终端交互次数。没有真实 Windows 或 macOS 扫描耗时结论。

### 实现与验证证据

- `lib/community/ux.mjs`：两套 TUI 共用状态、浏览器复用与安全恢复文案。
- `lib/installer/community-setup.mjs`、`lib/installer/community-wizard.mjs`、`lib/console-tui.mjs`：精简连接与日常操作、扫码控制、进度、重试及显式工具开启入口。
- `lib/community/qr-login.mjs`、`native-session.mjs`、`native-reader.mjs`：低频、有界身份验证；短暂可取消的会话排队；保留错误类型和部分证据。
- `config.mjs`、`setup-flow.mjs`：仅合并无关平台变化；同平台冲突拒绝覆盖。
- `scripts/test-community-ux.mjs`：8 组隔离用户旅程覆盖 UX01—UX16；`scripts/test-console-tui.mjs` 增加 UX17 非流动 stdin 回归。
- 真实 PTY：快速配置进入 Community → 知乎未连接 → 扫码连接入口 → Esc 返回；控制台进入 Community → 浏览器设置 → 扫描进度 → 来源菜单 → Esc 返回 → Q 正常退出。两次进程均返回 0；没有配置写入、浏览器下载或账号访问。此 Linux 环境来源菜单约 0.10 秒，不代表跨平台性能保证。
- `npm run prepublishOnly` 通过：**328 个文件语法检查、CI 策略检查、依赖审计 0 漏洞、100 个隔离测试入口全部通过**。
