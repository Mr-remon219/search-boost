# v0.2.4-beta.8：面向 Agent 的说明分层与工具选择

beta 预发布，仅推进 npm `beta`，稳定 `latest` 不变。沿用 beta.7 的接入管理及独立修复同意，不新增安装/修复权限。

## 改动

- 统一 MCP、Pi、DSH 的共享工具描述，直接指导 Agent 选择与调用，而不是只修改给用户看的文档。
- `fused_search` 可承担绝大部分公共 Web 检索，包括困难问题，不依赖 Jev。未配置 Jev 或 Adaptive 不可用时，使用已启用的 Fused 正常研究，不要求先配置、不调用锁定工具。
- `adaptive_search` 可用时，中高难度、不确定性高且需要按研究方向筛掉噪声、判断相关性的任务，优先使用它做更高质量的证据选择；可直接调用，不要求先试 Fused。直接检索足够或需要多查询角度、来源控制时仍用 Fused，不因配置了 Jev 就对每次搜索使用 Adaptive。更高质量是筛选目的，不是已经证明的质量提升或真值保证。
- 参数细节归 schema，常驻政策负责验证与权限，动态能力只报配置状态及缺失/禁用的合法路径，resource 提供按需示例与排障；hooks 负责递送政策，不执行检索或授予权限。
- 清除动态能力、DSH 政策及 MCP reference 中固定 32 候选的过期说明；当前可选参考按代码生成目标相关容量与分页期限，不改变实际容量。
- 明确主 Agent、searcher、summarizer 与工作流职责；区分 SearchBoost 的 Pi 研究 runner 与 pi-subagents，保留子工具隔离和失败边界。同步 Grok、Antigravity 生成资产及双语 README。
- 新增说明契约回归，覆盖 Jev 未配置、已配置、Adaptive 被显式禁用、实际 MCP/Pi/DSH 注册、注入去重与工具选择提示。

历史职责基准、功能演进及当前契约见 [prompt-contract.md](prompt-contract.md)。旧发布、审计与实验记录不改写为当前证据。

## 不变的行为

搜索/筛选算法、评分、排序、输入类型及数值边界、单次快照全体审查、历史恢复、网络安全与取消逻辑不变。不新增检索轮次、自动补读、累计预算或全局安装。凭据、权限、禁用状态和缓存重建同意边界不变。

## 更新与加载

```sh
npm install -g search-boost@beta --prefer-online
search-boost
# 管理 Agent 接入 → 刷新已有接入 → 选择范围
# 或刷新全部已有接入：
search-boost refresh -y
```

退出并重启受影响宿主和 MCP 服务。已安装的注入文件需刷新；运行时工具描述需实际服务加载新包。刷新保留已有状态，普通 `-y` 不授权 Grok 缓存重建。既有未固定版本的 npx MCP 启动项未改变，不能仅凭插件/全局包版本认定独立服务已运行 beta.8。

## 验证与发布边界

发布要求本地完整 `prepublishOnly`（语法、CI 策略、依赖锁审计、全部有毒调用者隔离入口），准确最终提交的四格 CI（Linux Node 22.13 / Windows Node 22 / macOS Node 22 / Linux Node 24），及实际 npm tarball 文件、版本和字节验收。CI 成功后才允许发布已验收制品到 npm beta；registry 暂未可见时只读核查，不盲目重发。

回归包含实际 stdio MCP、原生宿主注册/schema、生成资产、安装/global/npx 分发、搜索冻结回放、保存与恢复，以及用户文件/源码不变检查。这些验证证明交付契约，不证明真实 Agent 必然遵循提示词，也不证明在线搜索覆盖、实际质量增益、GUI 加载或付费服务行为。本次没有操作真实宿主配置或修复用户缓存。

## 回退

需要回退时，保留配置/事务备份，显式安装 `search-boost@0.2.4-beta.7`，按该版管理入口和 dry-run 审核后刷新已有接入并重启宿主。不要移动稳定 latest、删除用户 profile/数据或绕过独立信任同意来伪造恢复成功。
