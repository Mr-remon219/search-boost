> 本文融合历史审计与研究材料，统一结论并去除未采纳建议；替代原研究补充文档，不是两份报告的简单拼接。
> [设计规范](adaptive-fused-screening-plan.md)仍独立保存。本文的优化建议不自动成为产品契约或上线批准，也不是逐步实施清单。

## 一、结论先行

**原设计的骨架成立，而且与 Jev 的能力模型相适配。不能把“限制审核＋价值档位＋独立来源折扣＋独立偏好＋代码补量循环”整体判为过度设计。**

此前审计混淆了四件事：

1. 用户明确选择的产品取舍；
2. Jev 需要的固定选项、独立判断和代码组合；
3. 独立原型尚未接齐的运行时能力；
4. 已经存在、可以复现的实现错误。

尤其需要撤回“缺少更聪明的反馈循环是主要设计缺陷”和“多几个判断题就是显著多几次调用”的暗示。用户早已把 loop 弱化为“没搜够”，不是让 Jev 规划研究路线；同一 state 的多个判断可以批量并行取得。

修订后的判断是：**保留既定设计，修正局部实现、补齐集成边界，有限地简化真正重复的表达；不另造一个研究规划器，也不因为示例参数尚未校准就推翻公式。**

这不等于宣称已经胜过 fused。效果与完整任务成本尚待验证，但“还没有优势证据”不等于“设计不成立”。

### 综合判断与优先级

| 处置 | 项目 | 判断依据与边界 |
|---|---|---|
| **保留** | H/V/D/P 分工、固定选项、当前公式、有界朴素循环 | 符合已确认取舍与 Jev 能力；尚未校准不等于设计错误 |
| **集成前修复** | 文本安全绑定、请求尺寸、正贡献 provenance、局部失败产物、真实停止原因、取消/期限接口 | 已有确定性反例或明确集成契约；不归咎于公开 runtime |
| **补齐** | 有效软多样性、ranking/折扣选项标准、判断阈值版本、材料上下文 | 恢复既有能力或使决策可解释，不新增研究规划层 |
| **有限试验** | 单篇/小批/多篇打包、价值未知补读、confidence 诊断 | 先比较实际质量和完整成本；不直接改默认值或准入规则 |
| **低优先级可选实验** | 固定评分问题的上界停止 | 必须满足固定池、固定判断等前提；不能直接套到多样性选择 |
| **不新增** | 智能研究规划、模型生成查询、全量终审、confidence 直接评分、默认硬折叠 | 无项目证据支持额外复杂度或风险 |

最重要的新判断是：**同文多题适合批处理，不等于多文同批越大越好；应修尺寸边界，再验证打包粒度，而不是把四个判断维度拆成四次请求。**

## 三、来源证据与设计后果

历史审计与后续研究均先搜索、再读正文。下面区分官方能力描述、厂商示例、独立研究和项目推论；同一厂商的多篇页面不算多份独立实证。没有调用用户配置的 Jev 网关。

### 3.1 Jev 能力与边界

| 官方资料 | 已核实的能力/限制 | 对当前方案的影响 |
|---|---|---|
| [Introduction](https://docs.typesafe.ai/introduction) / [Choice](https://docs.typesafe.ai/primitives/choice) | 不生成自由文本；从调用方给定的选项中返回结构化答案 | 用户“不让 Jev 根据问题自己编选项”的边界正确；预设 ranking、档位、折扣、偏好可执行 |
| [Primitives](https://docs.typesafe.ai/primitives) | 同一请求的问题共享 state，独立并行评估；一个答案不会自动成为另一个问题的上下文 | H/V/D/P 可以同批取得，代码按资格决定消费哪些结果；逻辑上先审核，不意味着必须串行发四次请求 |
| [Speculative fan-out](https://docs.typesafe.ai/patterns/fan-out) | 推荐把条件性问题一并询问，再由代码忽略不适用的答案 | 不能仅因部分问题最终没用到，就判批量设计浪费；新增问题通常主要增加问题 token，而非一次完整往返 |
| [Composite scoring](https://docs.typesafe.ai/patterns/composite-scoring) | 推荐拆成独立维度，由代码控制权重和组合 | 保留价值、来源政策、偏好三种语义，与其架构方向相容；官方推荐不等于本项目参数已验证 |
| [Noul](https://docs.typesafe.ai/primitives/noul) | 0–1 表示“是”的概率，不是属性程度；阈值由代码决定 | 旧“值得保留的概率很高＝材料价值很高”的混淆值得修；不能把 0.9 直接当阅读价值的量度 |
| [Score](https://docs.typesafe.ai/primitives/score) | 支持预定义的有序档位；返回档位位置，可为概率加权的分数 | “Jev 不能自由生成评分标准”不等于“Jev 没有 Score API”。本项目 Choice 0–5 加 unknown 仍是合理离散契约，不必因此迁移 Score |
| [How to build](https://docs.typesafe.ai/concepts/how-to-build-with-system-one) | 代码负责流程；模型负责窄判断；仅在新数据或新选项形成真实依赖时追加请求 | 一个朴素的代码补量循环就是合适架构；不需要模型生成缺口、下一查询或全局完成判定 |
| [Models](https://docs.typesafe.ai/models) | 英文是主要训练语言、当前表现最好；当前官方模型上下文有总请求 64k token、state＋最长题 32k token 两个边界 | 英文输入有官方能力依据，但不能把厂商说明说成该任务的大量独立研究；批次不能只按 URL 个数限量 |
| [Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13) | 数学、日期比较、间接指令、大而无关的 state、对抗内容及跨题一致性存在局限 | 算术/集合规则留代码；保持问题和依据清楚；不能假设 Noul 与 Choice 对相似命题必然一致 |

两个必须保留的限定：

1. 官方对低延迟、额外题成本及稳定性的描述，不是当前自定义网关、当前材料长度下的实测。不能宣称真实调用成本已近于零。
2. 问题独立不等于 state 可以无限扩大。额外问题较便宜，与额外网页正文会占用输入、造成干扰，是不同的成本轴。

另外，不能从 Noul 的概率语义推出“它永远不能用于排序”。它可以排序某命题成立的可能性；本项目的问题是目标需要阅读价值档位，不能把较弱命题的成立概率偷换成材料重要程度。

### 3.2 后续研究带来的增量证据

| 来源（已读正文） | 支持的判断 | 不支持的外推 |
|---|---|---|
| [TypeSafe：Parallel questions](https://docs.typesafe.ai/cookbooks/parallel_questions) | 同一文档、同一 state 的多个问题可以一起评估，避免重复发送材料 | 不证明增加不同文档到 state 不影响质量；案例节省倍数不能套到本网关 |
| [TypeSafe：Classifying RAG passages](https://docs.typesafe.ai/cookbooks/classifying_rag_passages.md) | 官方例子每篇材料一次请求、一次问多个问题；代码路由、具名阈值、小池并发 | 示例不是禁止多文同批的 API 限制；其阈值不是本项目默认值 |
| [TypeSafe：Confidence](https://docs.typesafe.ai/confidence.md) | Choice/Score 的 confidence 来自选项概率分布；Noul 不带该字段；阈值需本域验证 | confidence 不是事实正确率、阅读价值或材料缺失的专用探测器 |
| [Elastic：Maximum Marginal Relevance](https://www.elastic.co/search-labs/blog/maximum-marginal-relevance-diversify-results) | 逐轮选择时平衡候选分数与相对已选项的重复度；基础分可来自自定义排序器 | 词法相似不等于同一文档；文中参数不能直接搬到本公式 |
| [Meng 等，SIGIR 2024：Ranked List Truncation](https://arxiv.org/html/2404.18185) | 所测管线中，监督式动态截断未展现稳定优势；合适固定深度可接近其效果/效率取舍 | 不证明所有动态停止都无用，也不支持把论文深度 20 设为本项目默认 |
| [Elastic：Exploring depth in a retrieve-and-rerank pipeline](https://www.elastic.co/search-labs/blog/elastic-semantic-reranker-part-3) | 所测模型/数据集出现提升后饱和、先升后降及持续下降；应比较自身质量—成本曲线 | 厂商实验不是 Jev 实验；其收益、比例和深度均不可直接迁移 |
| [Elastic：More skipping with block-max MAXSCORE](https://www.elastic.co/search-labs/blog/more-skipping-with-bm-maxscore) | 用得分上界跳过不可能进入 top-k 的候选，是已有检索优化思想 | 倒排索引算法不直接证明本筛选控制器正确 |
| [Fagin、Lotem、Naor：Optimal Aggregation Algorithms for Middleware，作者摘要页](https://www.wisdom.weizmann.ac.il/~naor/PAPERS/middle_agg.html) | 单调聚合、访问成本与阈值算法提供理论背景 | 仅核读作者摘要页，不声称完整论文定理适用于本原型 |

这些来源支持改进局部机制，而不是新增研究规划器。SIGIR 研究尤其反驳“动态停止必然优于合适固定深度”的预设；Elastic 的深度实验也反驳“越深必然越好”。两者共同指向小规模项目内比较，而非直接选择某个极端。

## 四、哪些设计应当保留

### 4.1 限制、价值、来源折扣、偏好，不应合成一个模糊判断

四者回答不同问题：

- 限制：能不能交付；没有通过就不能靠分数补偿。
- 价值：值得优先阅读到什么程度。
- 来源折扣：按明确政策，有意调整检索渠道对排序的贡献。
- 偏好：调用方喜欢的属性是否存在；不等于材料客观低价值或高价值。

例如，5 档综述没有公开代码偏好奖励；4 档实验材料因匹配偏好而排在前面，是用户明确接受的行为，不是排序异常。不能用“先按档位排序即可”抹掉 D/P。

来源折扣可以有意重复强化 ranking 已有的政策偏向。需要披露，不需要伪装成新增的质量证据。**它不必在每个池改变名次，才能被允许存在。**

### 4.2 循环可以朴素，不需要“更聪明”才合格

既定要求允许：预设 ranking → fused 候选 → 分批审核/排序 → 不足时处理更多未审候选；可选补读只补当前材料的依据。

是否先一次性审一个受限池、是否每批就尝试停止，是实现与预算取舍，不是“有没有真正 adaptive”的资格考试。循环须保证新增候选/新文本或有界失败恢复，不能拿相同缓存结果刷进度；但不需要创建研究计划器。

若从同一问题确实无法取得新候选，应该结束并交付已有材料，不能假设引擎存在未经验证的分页接口。

### 4.3 公式有来由，不应因复杂就推翻

原 `B(VD+C)` 会让价值与偏好贡献随低 B 同步缩水。新公式是为解决这个具体问题，不是凭空增加符号。

三个开发池中，示例参数下的纯 V 混合排序与“档位→B”相同，只说明该区间价值占主导；**不能据此断言公式冗余，或要求它必须在某个池产生不同名次。**

真正要检查的是：实际 B 分布下，价值、B、政策和偏好各自有多大影响，误分档后果能否接受。公式可以保留为待校准方案，简单端点可以做对照，但目前没有证据要求另换一套公式。

## 五、前几轮审计的撤回、降级与保留

| 此前判断 | 本次处置 | 原因 |
|---|---|---|
| “只有遍历，没有反馈循环”列为主要 P1 设计缺陷 | **撤回该定性** | 用户已明确弱化 loop；一次受限池扫描本身合理。需要的是预算/停止契约，不是更多研究智能 |
| 返回 1 条却审 20 条说明浪费 | **撤回推论** | top-1 不等于只审一篇；第 20 篇可能最好。此前 20 次调用来自人为 `batchSize:1`；默认 8 条批次是 3 次 |
| 多维判断、部分答案未用，表示额外模型调用过多 | **撤回一般化表述** | Jev 官方推荐同 state 批量独立判断。维度数量、题数、往返次数不能混为一谈 |
| 来源折扣重复 B、D 在夹具无效果，因此设计有问题 | **不成立** | 用户明确需要政策偏向；本夹具激活不足不能否定机制，也不能证明收益 |
| 公式与档位排序相同，说明应简化替换 | **降为校准与对照问题** | 存在明确历史动机；只观察了示例参数和窄 B 区间 |
| value unknown 没补读是违反既定契约的 P1 | **降为可选扩展/预算策略问题** | 原建议刻意是少量“条件不足”补读，允许首版不做。扩大到价值不足有意义，但不是追溯性改写原要求 |
| 0 档仍可能得到条件补读 | **保留局部优化问题** | 可消耗稀缺补读预算；脚本证明路径可达，未测现实浪费频率。不是整个补读设计失效 |
| 原型忽略 signal，所以 adaptive 不尊重取消 | **纠正范围** | 原型尚未声明/接入该接口；现有公开入口与客户端已有取消处理。集成时必须接齐 |
| 原型少元数据，说明 Agent 无法使用材料 | **收窄** | 已返回实际审查文本 `description`；basis/版本/日期丢失值得修，但不等于没有交付证据 |
| 测试显示已验证比 fused 更好 | **继续否定该效果主张** | 开发标签不独立，成本为模拟，F 行只是 B 序。可验证机制，不是验证真实收益 |
| 没有收益证据，所以设计不成立 | **撤回这种推论** | 未验证是证据状态，不是反面实证 |
| 默认关闭未经验证的折叠属于能力退化，应开启 | **不采纳** | 关闭是为避免已复现的误合并；应单独处理列表冗余，不重新默认开启不可靠折叠 |
| `mu` 不生效、URL 合并安全状态错配、零权重来源改变折扣 | **保留** | 都有确定性代码反例；属于局部实现问题 |

## 六、重新分级后的实际问题

### A. 集成前应修复的明确问题

#### A1. 文本与安全状态在 URL 合并时可能错配

位置：`lib/search/screening/controller.js:20–55`。

先放入 clear 的摘要，再合并同 URL 的 violation 正文，结果采用新正文却保留 clear；交换顺序变成 violation。这违反文本版本与许可绑定，不依赖 Jev 判断准确率。

**性质：明确正确性/安全边界缺陷。** 同 URL 不等于同一段受审文本。修复对象是快照合并，不需要重构产品定位。

#### A2. 固定条数批次可能超过已有客户端的请求上限

位置：`controller.js:234–235`；`lib/jev/client.mjs:439–441`；`lib/search/adaptive/limits.js:75–76`。

历史审计轮新增的可复现证据：8 条各 8,000 字符正文，经现有请求构建后，完整 body 为 **77,085 字符**；现有客户端/运行时请求上限为 **60,000 字符**。使用真实本地客户端、禁止网络的假 transport，得到 `request_too_large`，transport 调用为 0。

**性质：原型集成边界缺口。** 应复用现有 `requestFits` 等能力，按实际 state 和序列化请求边界打包，候选条数只作为上限；单篇仍超限时需明确处理，不能靠删掉硬条件题或盲目抬高限制消除错误。这里是本地字符上限复现，不冒充官方 token 上限或网关在线测量。

**进一步优化：区分同文多题与多文同批。** 官方批处理示例保持文档不变，只改变问题是否合并；官方 RAG 示例按材料分请求，Jev 限制说明提醒无关上下文干扰。因此 H/V/D/P 同批合理，但多篇不互相比较的文档共用 state 是另一个变量。

综合建议：尺寸保护应做；单篇、小批、多篇的质量/成本对照可试验；暂不强制一篇一请求，也不宣称大批答案必然不变。验证时先用固定答案确认打包不丢候选/题目、输出不变，再另测真实模型对 state 改变的敏感性。mock 不变性不能证明真实判断不变。

#### A3. 暴露了冗余修正参数，但没有真正使用冗余

位置：`controller.js:136–138`。

`redundancy:0` 导致修改 mu 也不改变结果。此前同池/合成对照表明可能重新堆叠镜像；这是列表层能力未接齐，不证明四项评分设计有误。

**性质：原型行为缺口。** 优先适配 `lib/search/results.js` 的 `selectDiverse`；未接齐前明确 μ 不可用。结合 MMR 资料，应保留候选自身的 `finalScore`，逐轮按已选集合计算 `selectionScore`，而不是一次静态扣分。

继续保留适用的来源上限，并验证镜像、同域不同内容、独立同名页面和版本差异；既看新增不同材料，也看是否挤掉唯一关键证据。新分数尺度不同，μ 与 fused 现有惩罚系数均不能照搬。软降权不等于文档身份合并，`dedupe:false` 保持。

#### A4. 来源折扣使用了非正贡献引擎

位置：`controller.js:52`；`policy.js:43–51`。

加入 rank 有记录但权重为 0 的 Exa，B 仍为 1.1、实际投票仍只有 Bing，snapshot 的 engines 却扩大；可用折扣从 `none/mild/strong/unknown` 变成 `none/unknown`。

**性质：来源语义实现缺陷。** 在中性策略下不改变分数，在启用政策折扣时可改变行为。应修正 provenance 投影，不借此删除来源折扣。

#### A5. 失败、停止与取消需要由真正的控制器负责

位置：`controller.js:195–199,231,248`。

- 第二个 judge 批次异常使整个 helper reject，已成功的第一批没有产物返回。
- 一个 pending 候选也可被纯排序 helper 标为 `candidate_pool_exhausted`。
- helper 未声明 signal/deadline 接口；现有公开 adaptive 的这些能力并未因此消失。

**性质：原型的故障隔离与集成契约。** 应保留已有效结果、真实披露未完成状态；取消不应被吞成普通失败后继续工作。纯排名函数不应自行猜测全局停止原因。

### B. 优化判断：补齐契约与有限试验分开

#### B1. 固定选项标准与判断阈值：应补齐

`judgments.js:29–43` 的 ranking 说明引用默认空的 `notes.presets`；`:114–115` 的折扣说明只是 `Policy discount: mild/strong`；scope 阈值内联为 `0.85`。

- 给三个 ranking preset 提供实际定义；缺失时明确报错或披露回退，不能假装模型读过不存在的说明。
- eligible 集合回答“允许选什么”；另需给出“何时选择 none/mild/strong”的标准。保留明示政策偏向，不把它包装成事实质量。
- 判断阈值集中、版本化并随产物保留，便于回放。示例值不因版本化就成为已校准默认；不要把 Noul 阈值直接用于 Choice。
- 验证条件边界与实际选择行为，不只检查提示词包含某些字样。中性默认与模拟标签不能验证非中性政策的真实选择。

#### B2. 补读：交付决策未定者优先，可选扩展

可试验允许“适用条件已通过、价值仍未知”的候选补读，并优先处理可能改变交付结果的信息不足，避免明确低价值项先耗尽预算。

不变边界：同 URL、有界次数、安全阻断不重开、新文本自带安全状态与版本、重判后仍可全部拒绝。新证据本来就可能提高或降低档位；不应断言“补读后不得提高档位”，而应检查重判后是否满足全部准入条件。

这不是对原 scope-only rescue 的追溯性违约判定，也不要求救回所有未知或临界档位。恢复率和误收率必须由独立材料验证。

#### B3. Confidence：先记录诊断，不直接新增行为阈值

专项代理建议将低 confidence 用于触发补读；综合官方语义后，仅采纳先保留实际返回的有效 confidence，缺失记 unknown。不立即把它接入准入、V/S 或补读规则。

低 confidence 可能来自档位边界、题目含糊或信息不足，不能直接改名为“材料缺失”。高 confidence 也不能覆盖显式 `unestablished`，更不能使条件未知自动通过。

最小验证：同一个已定档位仅改变 confidence，基础准入/评分应不变；显式 `unestablished` 在任何 confidence 下仍未知。以后如用于补读调度，需单独校准并验证净收益。

#### B4. 简化代码已确定的工作，保留有效语义

- **中性折扣**：代码已确定完全中性时可以不问模型，分别披露政策中性与来源缺失。但不把未测的同批题目成本列为主要瓶颈。
- **预过滤**：已安全阻断或基础分无效者无须再发判断；不能把未知事实当确定失败来剪枝。
- **scope/info**：两者部分重叠，也有通过依据和未通过原因的用途。现有保守一致性检查有理由；是否合并应看小样本行为，不宣称少一题一定更好，不增设重复的价值依据题。
- **输出上下文**：保留实际摘录，加回 basis、日期/版本及可回溯来源信息；分数细项可放诊断。不要求 Jev 生成自由摘要或增加全局解释器。

### C. 需要验证、但当前不能定罪的能力风险

- 复杂 constraints 被集中为“是否满足全部条件”这一题，可能超过 Jev 最擅长的窄判断；官方建议每个明确条件分别判断再由代码组合。可评估按调用方的数组项提问，但不要自动拆碎项内 OR、例外和实体绑定，更不能自行生成隐藏条件。
- 数字/日期等可机械计算的限制，应在有可靠字段时交给代码；不能让 Jev 猜缺失日期或把普通分类置信当事实核验。
- 大 state、对抗文本和含糊档位可能损害判断。官方风险说明支持做定向测试，不支持凭空报告现实误收率。
- 英文契约、各档位间距、来源政策、偏好权重及真实批次大小仍需在实际任务上观察；不能仅凭参数合法证明产品效果。

## 七、低优先级可选实验：评分上界停止

这是受 MAXSCORE/阈值算法启发的**项目内推导**，不是文献已经验证了本实现，也不是新的必需控制层。

已有公式 `S=D[λb+(1−λ)u]+εp`，`b=B/(B+τ)`。合法参数域中 D≤1、u≤u(5)、p≤p_max，因此未判断候选的保守上界为：

`U(B) = λb + (1−λ)u(5) + ε·p_max`

无偏好时 `p_max=0`，否则可取合法匹配值的最大值。未知准入状态不能被假设为失败：上界仍允许该候选最终通过。

**初始适用范围：** 固定候选池与 B、固定策略、候选判断不随调度变化、不再修改已判材料，并关闭多样性与折叠。已有至少 k 个合格结果，且所有剩余候选的上界均严格低于当前第 k 名时，可以停止剩余判断而保持这个固定评分问题的 top-k。

- 等分时继续，或显式处理完整 tie-break；实现须保守处理浮点边界。
- 不保证未检索材料不更好，不宣称研究完成，不提供全池完整判断统计。
- 新候选、补读重判、state 改变或多样性选择都可能改变前提，不能直接沿用保证。
- 真实 Jev 答案可能随 state 改变；固定模拟答案只能验证算法机制。

后续研究轮调用当前 `scoring.js`，用固定种子 72491 检查了 10,000 个随机参数/候选样本，未发现分数超出保守上界（断言容差 `1e-14`）。另用默认 τ=1、λ=0.5、u(5)=1、无偏好、D=1 验证：

| 场景 | 已判分数 | 剩余 B≤1 的上界 | top-1 决策 |
|---|---:|---:|---|
| 首条 B=10、价值5 | 0.954545 | 0.75 | 可停止 |
| 首条 B=2、价值3 | 0.458333 | 0.75 | 必须继续，后续价值5可能胜出 |

这是数值机制检查，不是生产控制器集成测试、穷尽证明或真实节省测量。当前优先修好尺寸、失败边界与列表能力；不为了加入此优化而关闭本来需要的多样性。

## 八、如何评价，而不把评测本身越做越复杂

保留当前组件回放作为工程测试即可，不需要推翻重写为庞大评测平台。效果判断至少区分：

1. **同池排序对照**：原生 fused 最终选择、相同准入集合按 B 排序、当前完整评分与列表选择。按需要加入简单档位序，检验公式作用，不要求每种规则都必须排出不同名次。
2. **判断与补读对照**：少量独立可核验材料，覆盖贴题但无实质、摘要不足的一手材料、反证、版本差异、镜像和独立同名文档。人工/独立核验 outcome，不能只重用 ranker 的档位标签。
3. **成本对照**：分别记录题数、请求数、共享 state 与新增问题输入量、并发与顺序阶段、限流、补读、总延迟及主 Agent 阅读负担；再比较完整任务成本。不能把题数当调用数，也不能把官方标价/速度直接套到自定义网关。
4. **打包与停止对照**：先比较少量单篇/小批/多篇配置及固定深度基线；若试验上界停止，与同池固定判断全扫描严格对照，前提不满足时禁用。离线打包不变性和真实 Jev 质量是不同验收项。

原有 LC/RAG 三组端到端报告是旧版本、单题单次、查询语言不同，且 fused 超预算、PDF 阅读存在独立故障。它能提示调查方向，不能作为当前未接线原型失败的证据。

循环只需证明在交付不足时能处理真实新候选/新文本，且在没有进展或预算耗尽时正确结束。不要求恢复研究充分性判定，也不预设“每批决策一定优于一次扫描”。

## 十、最终审计判定

**设计方向：保留。没有充分理由推翻既有 H/V/D/P 分工、固定选项或朴素补量循环。**

### 11.1 独立复审与复审后修复

两个只读独立复审（实现语义 / 测试与文档保真）给出的结论与主线程复现情况：

- **修复前的原始复审**：语义复审明确列出一个 blocker（短文本导致 `mu>0` 崩溃）、两个真实缺陷（补读请求绕过尺寸检查、无可用评估却报告池耗尽）及其他弱点；测试／文档复审的结论是无 blocker，但有一个测试保真缺陷及覆盖缺口。两份复审均无 shell、未执行测试；其中“未发现缺陷的目标”讨论的是已列例外之外的路径，不能概括成五项目标全部通过。本文此前“复审未发现 blocker”的概括以及对应交付回复不准确，现予纠正。修复后测试通过属于主线程验证，不是两位复审者对修复版的再次验收。
- 主线程随后对关键反例复现、结合代码检查修复并补回归；不是每条复审建议都有独立运行复现：① `shingleOverlap(null, …)` 让任一个短文本候选打断 `mu>0` 选择循环（`jaccard` 直接读 `.size`）；② 补读文本可到 20000 字符，绕过了打包用的 `requestFits`，超限请求会被客户端拒绝并误报为 `judge_failure`；③ 空/无效答案映射产生 `value_unavailable`/`scope_unavailable`，却仍报 `candidate_pool_exhausted` 且 `incomplete:false`；④ 补读读取跨过截止时间后仍会派发判断；⑤ 补读派发失败时内部曾保留新正文与旧判断的错配，现回退到补读前版本；原复审指出旧判断在这两类补读目标中仍会阻止准入，故不能声称已复现未审查正文被正常交付；⑥ 非 `clear` 安全状态仍被送判断（本运行期不可能准入）；⑦ `content:''` 吞掉同行 snippet，只有 `engines` 没有 `engineRanks` 的行丢来源，给出权重时 `provenance` 未按正贡献投影。
- 测试保真问题同样已修：intent 断言写在 judge 内部，会被批次失败处理吞掉而总是“通过”；打包缺少“不重复、不重排”断言；补读期的取消/超时/派发失败无回归；消融 trial 有两条无法失败的自证断言；消融中“不得发布 gold-fail”在本夹具内注定无法失败（已标注，需 tool-pass/gold-fail 对才能实测误收轴）。
- 保留的限制：折叠路径的 O(n²) shingle 重算尚未优化，折叠默认关闭；原复审将在途取消列为未验证边界而非缺陷，原型仍不能主动终止在途调用。不得把这条边界解释成可以漏报调用返回后的取消／超时。

### 11.2 后续主线程审查与修复

后续只读审查发现六项问题；以下是修复内容，验证结果另列，不冒充新的独立复审：

| 问题 | 修复及回归边界 |
|---|---|
| 末次读取／判断丢失取消或超时 | 异步操作返回／异常后及最终输出时检查状态；空、超限和抛错补读不绕过检查。保留有效结果，但中断使 `incomplete=true`，数量达标与 `run.halted` 分开披露。测试用可控时钟覆盖末次操作，不声称能终止在途调用。 |
| 摘录替换后元数据错配 | 按正文优先、长度、稳定字典序选择完整观察；snippet 与正文都绑定自己的版本、日期、标题等字段，缺失不借用旧值。基础分与评分版本另行绑定。回归覆盖顺序交换、等长、缺失元数据和正文优先。 |
| 自定义折扣条件部分覆盖／重叠 | 模型模式要求四档完整条件，拒绝所有非空不完整子集；请求声明适用性不明选 unknown，已确立条件按 strong > mild > none。判断契约版本升至 `screening-judgement-v2`；这是明确的政策优先级，不是引擎质量推断。未测真实模型遵从性。 |
| 非法评分／数量参数先消耗调用 | 在外部操作前验证评分参数与正整数 `maxResults`；回归要求非法输入的 judge/read 调用数均为零。 |

| 原始复审结论被错误概括 | §11.1 纠正 blocker 结论、复现范围和“未审正文被交付”表述，区分修复前复审、主线程修复验证和尚未进行的修复版独立复审。 |
