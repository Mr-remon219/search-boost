# v0.3.0-beta2：原生中文社区读取与控制台修复

版本：**0.3.0-beta2**；npm 通道 **`beta`**，Git 标签 **`v0.3.0-beta2`**。只发布 `v0.3.0` 开发分支，不移动 npm `latest`。源码和标签不证明 registry 已发布，请查询实际状态。

## 安装

```bash
npm install -g search-boost@beta
# 固定本次版本：
npm install -g search-boost@0.3.0-beta2
search-boost tui
```

已有宿主须按实际接入方式刷新后重启 / 重连，运行中适配器不会自动加载新代码。无参数 `search-boost` 保留快速配置向导。

## 相比 beta1 的变化

- **项目内部原生读取**：增加 `xiaohongshu-native`、`zhihu-native`、`bilibili-native`，使用各平台的 SearchBoost 专用 Chromium 会话。可选、固定版本的 `playwright-core` 不下载浏览器，不读取个人 Chrome profile，不自动登录或切换默认来源。本人执行 `search-boost community-login <platform>` 并确认，再明确选择「站内正文 / Station content」。详见[接入与安全恢复](community-search.md#会话和接入)。
- **讨论完整性**：小红书评论 / 回复、知乎问题 / 回答 / 评论记录身份、正文、分页和精确计数。仅在当前会话可读范围的必要部分全部验证后标 `complete`；缺页、未知 / 近似计数、风控、正文不足、容量或时间限制保持 `partial`。不把样本称为平台全量。
- **B站输出**：读取专栏、公开笔记和 Opus 可读文字；视频块按标题 → 公开笔记主体 → 评论补充 → BV 号组织，保留附件各自的日期与状态。不抓视频转录，不使用私有笔记接口，不以评论日期代替视频日期。Opus 发现仍可能使用网页索引，详情覆盖明确标注。
- **索引质量与边界**：过滤已识别的平台错误 / 欢迎页，保留其他引擎有效摘要；未知日期仍保守过滤。网络请求沿用代理 / 地址 / 取消约束，拒绝重定向，不将代理失败降级到直连。路由拦截不是操作系统级出口沙箱。
- **控制台交互**：不支持额度接口的引擎明确提示；单动作入口直接打开；小终端和缩放时不允许不可见确认 / 输入；长说明换行，超大粘贴原子拒绝，并提示并发配置变更后刷新。

## PR 审查与修正

[PR #36](https://github.com/Mr-remon219/search-boost/pull/36) 的最终修复 head 为 `6a5d9f7`，合并提交为 `3a07316`。合并前新增反例并修正：

1. 两处 Playwright `waitForFunction` 选项错误地传入第二个参数，声明的 15 秒超时未生效。
2. 评论树只检查父 ID 存在，跨根引用、循环、重复 ID 或根身份不一致可能被误标完整；累积和公共投影现在均重新校验。
3. B站 Opus 发现误用 snake_case 参数，内部适配器回退到 X 域名及默认预算；现在使用正确契约，并将用户和 provider 的取消 / 超时信号传到引擎。
4. 残留空白 / 损坏 / 复用 PID 的锁继续保守拒绝复用，但错误信息和文档提供安全人工恢复步骤，不增加强制解锁。

独立安全审查子任务返回了报告，但因缺失允许列表中的 `x_search` 工具被标记 failed；未作为成功的独立门禁。父任务直接核实相关线索、复现并回归。详见[审查记录](community-retrieval-fix.md)。

## 验证与限制

修复后的完整本地门禁 `npm run prepublishOnly` 通过：95 个隔离测试入口、语法和 CI 策略检查、依赖审计 0 vulnerabilities。控制台 47 项测试通过。最终 PR head 的 [CI](https://github.com/Mr-remon219/search-boost/actions/runs/37882398637) 在 Ubuntu Node 22.13.0、Windows Node 22、macOS Node 22 和 Ubuntu Node 24 上全部通过。发布版本元数据及文档更新后，还须对最终发布提交运行门禁并等待 CI。

没有使用真实登录会话运行三平台 Chromium 验收，也没有执行真实付费搜索 / 模型请求。离线测试不证明线上正文 / 全部评论可读、平台覆盖、登录流程兼容或运行中宿主已加载；未发现剩余可复现阻断项不等于没有任何 bug。

## English summary

Install `search-boost@beta` or pin `0.3.0-beta2`; stable `latest` is unchanged. This beta adds explicitly initialized, dedicated Chromium readers for Xiaohongshu, Zhihu and Bilibili, evidence-based discussion completeness, public-note-first video blocks and console interaction fixes. Review corrected wait timeouts, comment graph validation, Opus discovery contracts and cancellation propagation, and documented conservative lock recovery. No automatic browser install/login or personal profile access. Offline tests and cross-platform CI do not establish live authenticated retrieval or exhaustive platform coverage.
