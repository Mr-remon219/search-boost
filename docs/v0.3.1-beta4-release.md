## 这一轮改了什么

- 同一 URL 合并时，主行是排序赢家，与来源顺序无关。主行缺失 `summary` 时，另一家的 `null` 或 `""` 不能把顶层写成 `null`。只有非空摘要能补上缺失、`null` 或 `""` 的主行。provenance 仍按各源原来的 missing、`null`、`""` 或非空摘要记录。非空摘要不写进 `snippet`，`snippet` 也不写进 `summary`。两源两种顺序和三源都由 `scripts/test-v031-beta4.mjs` 覆盖。规则写在 [字段契约](./v0.3.1-beta1-fields.md)。
- `outcome` 五态出现在文本和 MCP `structuredContent`，包括 `isError: true` 的搜索结果。schema 用 zod 实测解析，不只在成功分支补字段。HTTP 200 且零条仍是成功。没有结果对象的意外异常不伪造 outcome。
- 引用 URL 和各源 provenance 保留非空片段。去重键仍去掉片段，`#a` 与 `#b` 仍是一行。不编造标题或来源。
- title、snippet、summary 全空时不再算命中。`warnings` 保留引擎和原始 URL（含片段）。不补标题或摘要。引擎本身成功时 outcome 仍是 `empty_success`。
- 轻量首页中文免 Key 说明改成完整句「自动搜索：免 Key 引擎。」引擎名单另起一行，不再把「引擎。」留成被换行切开的残句。取消后仍回到上一项已完成的菜单条目；这是 beta.2 已锁定的焦点，本轮不改成停在被取消的那一项。没有新入口。

## 升级、回滚、备份

在隔离的 `HOME` 和 npm prefix 里，用默认 npm 脚本（不要加 `--ignore-scripts`）按 beta.1 → beta.2 → beta.3 → beta.4 安装上面三个不可变包和本轮包，再把 beta.4 装回 beta.3，以及装回由 GitHub tag `v0.3.0` 打出的包。可执行脚本是 `scripts/verify-v031-beta4-upgrade.mjs`。它不在 `npm run test:isolation` 里，因为 CI 机器没有这些不可变 tarball。脚本开头隔离 HOME，不读真实宿主配置。

保留且每次安装后按字节和权限核对：

- `~/.search-boost/config/keys.json` 的 mode `0600`、白名单、自定义 Base URL
- 无关 MCP JSON
- 用户 canary 文件

`search-boost refresh -y` 只刷新已有接入，不删除 keys。安装和重装也不改这些文件。

回滚到 0.3.0 之后，代码回到旧的 DeepSeek Anthropic messages 路径：默认基址 `https://api.deepseek.com/anthropic/v1`，请求 `{base}/messages`，工具 `web_search_20250305`，头里有 `x-api-key`、`Authorization: Bearer` 和 `anthropic-version`。keys 文件不会被改写。如果 beta 期间把 DeepSeek 基址存成了 `https://api.deepseek.com`，0.3.0 会请求 `https://api.deepseek.com/messages`，那不是 0.3.0 的默认。要恢复默认，清掉这条基址，或设回 `https://api.deepseek.com/anthropic/v1`。非 DeepSeek 的自定义基址保持原样。

没有付费 live 调用。脚本没跑到的步骤标 NOT RUN。
