# v0.2.4-beta.6 修复说明

本版本针对按报告顺序记录的 [BUG-001–005](./v0.2.4-beta.5-bugs.md)。它是 beta 预发布，只推进 npm `beta`；稳定 `latest` 不变。以下“修复”指产品实现与隔离回归，不表示真实宿主已重启、历史用户配置已自动修复或上游服务已恢复。

## 修复内容

1. **Grok 旧登记升级**：更新前后统一使用 legacy-aware 身份发现，仍要求当前 source 和缓存文件身份/字节匹配。旧名称本身不再误报；旧缓存、错误源或不可核验缓存仍失败并给出明确诊断。不自动 uninstall/reinstall、启用插件或授予 `--trust`。
2. **Update 历史状态与 DSH 重复同步**：缺失的历史项目作为 `[跳过]` 披露并保留，不再阻塞有效目标；明确指定的无效 workspace、真实配置/载荷失败仍阻塞。Codex 拒绝异常标记时报告实际配置路径、缺失/重复/反序及行号，保持 TOML 不变。DSH 只有来源、版本、payload、bundle 与 owning-host resolver 全部验证且没有旧包迁移时才能 already-synced，避免多余 add、备份和改写；无相关宿主变更时复用验证，有旧包移除时重新验证。共享锁与串行资源边界不变。阶段事实与目标耗时保存到 `state/last-upgrade.json`；`hostDispatches` 指包操作派发，验证自身仍可能启动 resolver 探针，不宣称零进程或真实墙钟提速。
3. **X / community 输出契约**：DSH 严格 schema 类型化接纳 `engineStats`、`enginesUsed`、`warnings`；MCP 的声明与结构化输出也保留这些诊断。community 与普通网页共用公开行投影，移除 `created_at`、`bestIndividual`、`groupEvidence`、`votingEngines`，保留日期、公开评分与来源。没有 blanket 放开额外字段。fetch 的二进制拒绝新增 `nul_byte` / `control_byte_density` / `binary_content_type` 原因，HTML MIME 与字节拒绝不再混淆；保持所有网络、二进制和 403 边界。
4. **默认平铺 TUI**：完整十四项首页，设置中可选持久化 folder；旧语言设置默认 flat。共享动作、导航返回、原子/锁定保存、损坏设置不覆盖和 dry-run 不保存均保留。引擎配置可任选单个引擎且保留其他凭据/路由；只提供适配器可运行且有 Key 的启用选项，不依赖 Clack 0.10 不支持的 disabled option。Update 先展示范围，再明确开始 / 返回。独立 `config keys` 与首次配置仍保留逐项引导。
5. **Adaptive 参数协调**：有效容量贯穿真实 snapshot 截取、缓存键和诊断。目标≤10 保留 32；更大目标按原 10/32 的余量比例 `ceil(max_results×32/10)` 扩容，最高公开目标 50 对应 160。仍只做一次检索、判断完整声明快照；不保证上游供足或筛选后足量。新增 `valueJudged` 区分有效价值答案与准入计数 `qualityAssessed`。软页容量从 45,000 调整到 96,000 UTF-8 字节，依据 16,000 元数据预算、至少三条 8,000 字符中文摘录和字段开销，保持准确摘录、完整集合、超软限单条告警和零网络翻页。

评分系数、价值等级、偏好软语义、community 决策、单次检索架构不变。较大目标会增加 Jev 判断量；160 个实到候选四条批次约需 1 次策略 + 40 批判断（长文本拆批与重试另计）。数值依据详见 [Adaptive 审计增量](./adaptive-logic-audit-note.md#9-beta6-实现与数值依据)。

## Windows 现场与未解决归因

PowerShell 只读确认 Windows 当前安装 beta.5、五个缺失目录登记在 `C:\Users\Administrator\.search-boost\state\upgrade-projects.json`，默认 Codex 文件仅有第 594 行 END、没有 START。调查进程从 WSL 继承的 CODEX_HOME 不证明原 TUI 的实际配置来源；名称、提交年代也不证明历史条目由哪次测试写入。没有删除登记、修补真实 TOML、升级 owning DSH host、清理 profile 或改动真实插件。

Windows Node 22.23.1 下，通过 PowerShell 执行四个新增隔离入口通过，观察的四个用户状态文件哈希 / 存在性不变。升级 fixture 初次使用 junction 指向 WSL UNC 源导致清理失败，改为 UNC 可用的目录符号链接并增加私有临时目录清理重试后通过；这不是升级真实 profile 或更换宿主。跨 WSL 使用 Linux 依赖时，真实 PDF 抽取因缺少 Windows optional native binding 跳过，不能把这当作完整 Windows 工件验证，须依赖正确安装 Windows 依赖的 CI。

仍未查明：Grok 原生更新为何留下 0.2.0 缓存；原始 X HTML 字节拒绝 / Jina 403 的传输原因；原四次 adaptive 完整页面的碎页形状；真实 Windows 八个 DSH profile 的墙钟耗时。GUI 重启、真实付费 Jev/X 或语义质量不是离线回归的证明范围。

## 升级与回退

```sh
npm install -g search-boost@beta --prefer-online
search-boost upgrade --sync-only -y
```

完全退出并重新启动相应宿主。配置异常或旧 Grok 缓存不会因为版本已更新而自动获得信任或被覆盖，应按实际诊断审核。若需回退，可显式安装 `search-boost@0.2.4-beta.5` 再同步；较新语义/用户配置不会被保证自动逆迁移，先保留备份并查看 dry-run 范围。不要移动 npm 稳定 `latest` 标签。
