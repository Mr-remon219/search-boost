# SearchBoost 0.3.0 release notes / 发布说明

本文件描述 GitHub `v0.3.0` 的行为。它随当前 `0.3.1-beta.4` 包一起发出，但不是本候选的安装或回滚步骤。唯一权威指南是 [0.3.1-beta.4 说明](./v0.3.1-beta4-release.md)。registry 上没有 `search-boost@0.3.0`。不要执行那条 registry 安装。

## Highlights / 重点变更

1. **Yahoo is removed.** Explicit `yahoo` engine or weight inputs are rejected. The keyless free pool is Bing, DuckDuckGo, Exa-free, and AnySearch.
   **已移除 Yahoo。** 显式传入 `yahoo` 引擎或权重会被拒绝。免 Key 免费池为 Bing、DuckDuckGo、Exa-free 与 AnySearch。
2. **Page proxies fail closed by default.** When an HTTP(S) proxy is selected for page fetching, requests stop with `proxy_trust_required` until you set `SEARCH_BOOST_TRUSTED_PROXY=1` for a proxy whose remote DNS and destination ACLs you trust. A failing proxy no longer falls back to a direct connection (`proxy_fallback_disabled`); set `SEARCH_BOOST_PROXY_DIRECT_FALLBACK=1` only if you accept direct egress and exposure of your local egress IP. The two switches are independent, also accept `true`, and belong in the MCP server environment; restart the server after changing them. See [network policy](network-policy.md).
   **页面代理默认拒绝。** 页面抓取选中 HTTP(S) 代理时，默认报 `proxy_trust_required`；只有信任代理的远程 DNS 与目标 ACL，才设置 `SEARCH_BOOST_TRUSTED_PROXY=1`。代理失败不再自动直连（`proxy_fallback_disabled`）；只有接受直连出口及本机出口 IP 暴露，才设置 `SEARCH_BOOST_PROXY_DIRECT_FALLBACK=1`。两个开关互不替代，也接受 `true`，写入 MCP 服务端环境后重启服务。详见[网络策略](network-policy.md)。
3. **Enabled API keys join default searches and may incur charges.** When `fused_search` omits `engine_pool`, it uses your enabled keyed engines (including the new Firecrawl and Keenable) if any are available, otherwise the keyless pool. Provider charges may apply; check with the provider. To stay keyless for a search, pass `engine_pool: "free"` and do not list keyed engines in `engines`. To stop a keyed engine from being used by default, disable it or remove its key with `search-boost config keys`.
   **已启用的 Key 会进入默认搜索，可能产生费用。** `fused_search` 省略 `engine_pool` 时，只要有可用的已启用 Key 引擎（含新增 Firecrawl、Keenable）就使用它们，否则使用免 Key 池。可能产生费用，以服务商为准。单次只想免 Key，请传 `engine_pool: "free"`，且不要在 `engines` 中列出 Key 引擎。若不想默认使用某个 Key 引擎，用 `search-boost config keys` 停用或删除其 Key。
4. **Uninstall removes host integrations, not the npm package.** Interactive `search-boost uninstall` previews the selected hosts and asks for confirmation with **No** as the default. An explicit `--target` runs immediately without confirmation, even without `-y`. Use `--dry-run` to preview. Remove the package itself with npm.
   **卸载移除的是宿主接入，不是 npm 包。** 交互式 `search-boost uninstall` 先预览所选宿主再确认，默认 **No**。显式 `--target` 即使不加 `-y` 也会立即执行、不再确认；可用 `--dry-run` 预览。软件包本身用 npm 卸载。

## Other changes / 其他变更

- MCP results keep community content and typed `community_data`; Web and X rows stay compatible.
  MCP 结果保留社区正文与 `community_data`，Web 与 X 结果保持兼容。
- Dependency compatibility updates, including Zod 4 schemas, with the audit gate unchanged.
  依赖兼容性更新（含 Zod 4 schema），audit 门禁不放宽。
- The npm package ships runtime files, root user documents, SECURITY.md, and user documentation only.
  npm 包只包含运行文件、根用户文档、SECURITY.md 与用户文档。

## Security fixes / 安全修复

- API keys and endpoint settings are read only from your own configuration store or an explicitly selected file. A key file inside the current workspace is no longer picked up automatically.
  API Key 与端点配置只从你自己的配置库或显式指定的文件读取，不再自动采用当前工作区里的 key 文件。
- Page fetching applies stricter destination checks on every hop and recognizes more non-public address forms.
  页面抓取在每一跳执行更严格的目标检查，并识别更多非公网地址形式。

## Install or upgrade / 安装与升级

当前候选不从 registry 安装或回滚 `0.3.0`。GitHub `v0.3.0` 的 annotated tag 对象是 `12428996dd1aef92f0aedf78ed77066fd59cdbec`，它指向提交 `61c428b786230e71d7a84b2c417da4a9ac246d54`。打包这个提交的步骤、配置备份和 Base URL 恢复只写在 [0.3.1-beta.4 说明](./v0.3.1-beta4-release.md)。装上对应包之后，`search-boost refresh -y` 刷新已有宿主接入，不删除 keys。配置里的基址在 `engines.<name>.baseUrl`，不是顶层 `baseUrls`。
