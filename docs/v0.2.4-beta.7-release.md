# v0.2.4-beta.7：管理 Agent 接入

beta 预发布，只推进 npm `beta`；稳定 `latest` 保持 0.2.3。实施依据和实际验证边界见 [管理接入 note](agent-integration-management-note.md)。

## 改动

- 移除 SearchBoost 软件包自更新命令 `upgrade` 和首页“更新 SearchBoost”。软件包版本由用户通过 npm 更新；一次性旧 npm 包名 `migrate` 仍保留。
- “管理 Agent 接入”统一包含安装、刷新、卸载，保留平铺/文件夹布局与语言偏好。操作完成留在管理子菜单；卸载预览实际范围、默认取消。
- 新 `refresh` 用当前持久安装的软件包同步已有接入，不查询 npm 新版本、不自动更新全局 SearchBoost。TUI 可选精确 scope/profile，按实际资源去重；取消勾选不派发、不删除，之后新增目标不扩大选择。凭据、权限、禁用状态与无关字段保留。
- Grok 安装/刷新共用身份、源和缓存验收，已有同源登记不重复盲装。先原生 update 再验字节；陈旧缓存需独立明确授权才能让宿主 `uninstall --keep-data` 后 `install --trust`。确认绑定源/缓存指纹、名称、路径及仓库身份；禁用、不同源、共享仓库和不可验证身份拒绝自动重建，不直接覆盖宿主缓存。旧名称数据原址保留，不保证自动迁移复用。
- 普通 `-y` 不授予缓存重建同意。刷新进行中的确认 Esc 视为拒绝重建，不成功硬退出、不打断兄弟事务；陈旧缓存仍报告不完整。安装部分失败显示失败目标而非“安装完成”。移除后重装失败报告可能缺失/部分登记，并说明审核来源后使用安装入口恢复。
- 当前 README、TUI、迁移、Pi 子代理与 DSH 接入文档同步；历史 beta.5/beta.6、早期审查与布局设计保留当时证据，并指向当前文档。

搜索/Adaptive 架构、评分、容量、翻页语义及公共搜索字段没有改变。

## 使用

```sh
npm install -g search-boost@beta --prefer-online
search-boost
# 管理 Agent 接入 → 刷新已有接入 → 选择范围
# 或刷新全部已有接入：
search-boost refresh -y
search-boost refresh --dry-run
```

完全退出并重新启动相应宿主。Grok 缓存若仍陈旧，审核源和数据保留影响后，在交互提示中**单独**确认，或显式运行：

```sh
search-boost refresh -y --repair-grok-cache
```

该选项明确同意可能的保留数据卸载与信任重装，不是普通刷新必选项。刷新不会重新安装已不存在的插件；源码或登记异常须先解决，不要仅删除锁/历史记录以绕过保护。

## 验证与限制

本地完整 prepublish 门禁：语法 240 文件、CI 策略、依赖审计 0 漏洞、72 个隔离入口（用户状态与源码不变），含生成资产、实际 npm tarball/global/npx、搜索冻结基线及宿主替身回归。两项独立只读审查发现的可达错误经针对性红绿和完整门禁修复。准确发布提交仍须 Linux Node 22.13 / macOS Node 22 / Windows Node 22 / Linux Node 24 四格 CI 与实际打包验收通过。

Grok 1.0.46 使用私有 HOME/socket 原生 CLI 验证更新与重建；集成实验中的旧 author/cache 字节为人工 fixture，旧 slug 场景为宿主替身，不证明历史缓存的来源或真实用户插件已修复。没有操作真实 Grok/DSH 配置，GUI/付费模型/API 会话未覆盖。Grok 插件中原有未固定版本 npx MCP 启动配置未改；插件缓存版本不证明该独立服务进程运行 beta.7。

## 回退

需要回退时先保留配置/事务备份，再显式安装 `search-boost@0.2.4-beta.6`，按该版接口和 dry-run 审核同步。新状态/权限与数据不会被保证自动逆迁移；不要移动稳定 latest 标签，不要删除用户 profile 或历史项目记录来伪造成功。
