# 0.3.1-beta.1 来源字段契约

MCP、CLI 摘要、Pi 和 DSH 的 `fused_search` 使用同一结果对象。没有并列的第二套状态字段。

| 字段 | 含义 |
| --- | --- |
| `routeExplanation` | 为什么是这些引擎。不表示又调用了别的引擎。 |
| `engines` / `enginesUsed` | 结果来自哪些引擎，以及这次实际用过的引擎。 |
| `engineStats.<name>.attempts` / `successes` / `errors` | 计划调度次数、成功次数、失败次数。一次调度里的 HTTP 重试不加进 `attempts`。 |
| `engineStats.<name>.transportRequests` | 可选。该调度里的 HTTP 次数，含重试。没有内部重试的引擎不带这个字段。它不等于 `attempts`。 |
| `engineStats.<name>.note` | 失败类：`http_401`、`timeout`、`missing_key`、`invalid_request`、`cancelled` 等。不含响应正文和 Key。整条 note 最长 120 个 JavaScript 字符。超出时保留开头和结尾，中间用 `…`，不再只留开头。 |
| `outcome` | `results` 有命中；`partial` 有命中且至少一家失败；`empty_success` 是被调用的引擎 HTTP 成功但零条；`unavailable` 一家都没调用；`failed` 调用过且全部失败。它不增加请求。 |
| `results[].title` | 引擎没给标题时是空字符串。不用 URL 填标题。 |
| `results[].url` | 引用地址保留路径和查询，去掉片段。用户名或密码、非 http(s) 的地址整行丢弃，不当成命中。 |
| `results[].provenance` | 去重后每一家仍留一条。`summary` / `siteName` 有观察时写在对应条目上，不从另一家抄进缺失的来源。 |
| 去重键 | 协议和主机小写，去掉 `www`、路径末尾斜杠、片段和跟踪参数（`utm_*`、`pk_*`、`mtm_*`、`via`、`fpr`、`gclid`、`fbclid`、`mc_cid`、`mc_eid`）。片段是同一篇文档，`#a` 与 `#b` 合并，引用 URL 也不带片段。路径大小写和其他查询参数保留，所以 `?id=1` 与 `?id=2` 不合并。 |
| `url` / `title` / `snippet` | 证据。`snippet` 是短摘录，给 UI。空字符串保持空，不用 URL 或 summary 填。 |
| `summary` | 可选。官方 Search 的长摘要，给 agent。缺失时没有这个字段；提供了 null 就保持 null。不写入 `snippet`。 |
| `siteName` / `authority` / `rerankScore` / `published` | 来源有则保留。未知为 null，不编造。 |
| `provenance` | 去重前的观察。合并后的行仍能看到引擎、名次和 URL。 |
| 工具是否错误 | 结果为 0，且没有任何一次成功调度（选定源都没被调用，或每次调用都失败）。HTTP 200 且 `results` 为空是成功零条，不是错误。部分引擎失败但仍有结果不是错误。 |

去重键仍是现有的 URL / X post id。先出现的标题和摘录保留，后来的来源记入 `provenance` 和 `engines`。顺序仍由现有共识分和稳定键决定。

文本清理只做：NFC、去掉控制字符和双向控制符、解码六个命名实体、去掉简单 HTML 标签。`a < b` 保留。这不是证据真伪判断。
