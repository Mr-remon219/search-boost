# SearchBoost 0.3.1-beta.3

版本：`0.3.1-beta.3`。这是同一分支上的候选，不是稳定版，也没有 `npm publish`。registry 上没有这个版本。不要执行 `npm install -g search-boost@beta` 或 `npm install -g search-boost@0.3.1-beta.3`。

上一轮已交验的包是 `896c93c` 的 `search-boost-0.3.1-beta.2-896c93c.tgz`（sha256 `fa8476804d9ebbaec26e9b53dedde76411edd5d94e908ac58666ac40b6ea72c4`）。本轮不改那个文件。

beta.2 的界面回放 `docs/v0.3.1-beta2-ui-before.txt` 与 `docs/v0.3.1-beta2-ui-after.txt` 只在 git 树里。它们不在 beta.2 的 tarball 里，回放脚本也不在包里。说明见 [beta.2 说明](./v0.3.1-beta2-release.md)。

安装这一轮候选：

```bash
npm install -g /absolute/path/to/search-boost-0.3.1-beta.3.tgz
search-boost --version   # 必须打印 0.3.1-beta.3
```

## 这一轮改了什么

- 引用 URL 保留路径和查询，去掉片段。去重键同样去掉片段：`#a` 与 `#b` 是同一篇文档，合并后两边的 provenance 都留着。`?id=1` 与 `?id=2` 不合并。跟踪参数不同的同一页仍合并。
- 引擎没给标题时标题是空字符串，不用 URL 冒充。无效或带用户名的 URL 整行丢弃。
- 同一页合并时，任一家的非空 `summary` 仍留在结果或 provenance 上。`null`、缺失和 `""` 不互相改写，除非缺失或空的一边可以补上另一边已有的非空摘要。
- `outcome` 区分 `results`、`partial`、`empty_success`、`unavailable`、`failed`。它不增加请求。显式点名一家不可用的 API 时，`enginePool` 仍是那家的池，不会写成 requested free pool。
- DeepSeek 收到与主 query 完全相同的 `queries` 项时只派发一次。不同的 query 仍各派发一次，不超过复杂度上限。

可运行样本是 `scripts/test-v031-beta3-results.mjs`。它使用 fixture 引擎，不联网，也不打印 Key。

## 测量口径

事先登记：本轮不声称网络变快。进程内循环的 wall time 只有在中位数差距大于两边较大的极差时才算有差别，否则是 inconclusive。决策数字是计划派发次数、结果条数和 `outcome`。没有 live 付费 Key，样本都是 mock。

本机 5 次 fixture：median 0.247ms，range 0.359ms。range 大于 median，wall time 记 inconclusive。5 次的 attempts 都是 1，rows 都是 1，outcome 都是 results。beta.2 对同一对完全相同的 query 会派发 2 次。
