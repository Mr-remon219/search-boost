# v0.2.5-beta1：统一专用判断模型适配（Jev / Laya）

源码版本为 **0.2.5-beta1**；不代表 npm 已发布，也不代表任何宿主已重载。此更新只注册 Jev 与用户自行部署的 Laya，不加入通用聊天模型、reranker 或模型部署管理。

## 1. 已接入的路径

`adaptive_search → DecisionClient → DecisionRegistry → 选中的 adapter → 受控传输`

- `lib/judgment/registry.mjs` 是可信注册点。provider、模型列表、能力、配置校验和客户端工厂由代码登记；用户配置不能导入模块或执行代码。
- 同一研究运行冻结一个 profile；策略与材料筛选使用同一客户端。更改 active profile 只影响下一次研究，不中途切换，也不自动回退另一个提供方。
- Jev 保留 TypeSafe `/systemone` 与 Vercel 官方 SDK evaluation 路径。Vercel 的请求端点是 `https://ai-gateway.vercel.sh/v4/ai/evaluation-model`，不是聊天补全。
- Laya 使用 API 前缀追加 `/systemone`，显式选择 `english`、`multilingual` 或 `typed-decisions`。不接受 `auto`。不安装 Python、下载模型、管理 GPU、部署服务或训练。
- 输入、固定题目与选项、原文检索、N_off 单快照流程、Fused 原分和原型评分公式不变。confidence 不加分、不改准入、不进行跨提供方标定。Laya confidence/answer_confidence 仅作协议诊断，不冒充 Jev confidence。
- 没有第二轮搜索、查询扩展、自动补读或累计成本/token/请求次数/整次运行时限停止。原来的真实单请求超时、有限重试、响应与载荷保护、认证/限流错误、网络安全和显式取消继续生效。

## 2. 配置与迁移

TUI 首页 **判断模型（Jev / Laya）**（文件夹布局：服务与凭据 → 判断模型）可新增、编辑与启用 profile。它从同一注册器产生模型选择；输入 Vercel URL 后只提供 `typesafe-ai/jev`。确认前显示真实目的地及将发送的问题、方向和必要片段。取消与 dry-run 均不写配置，不测试连接。

配置只写用户级 `$SEARCH_BOOST_HOME/config/judgment.json`，默认 `~/.search-boost/config/judgment.json`，使用私有原子写入。例子是格式说明，不包含真实密钥：

```json
{
  "activeProfile": "local-laya",
  "profiles": {
    "local-laya": {
      "provider": "laya",
      "baseUrl": "http://localhost:8000/v1",
      "transport": "systemone",
      "model": "multilingual",
      "authMode": "none",
      "apiKey": null,
      "options": { "max_len": null, "head_max_len": null }
    }
  }
}
```

- Jev 要求 Bearer Key；Laya 可明确无 Key，绝不发送空 Bearer。如自行部署的网关要求 Key，选 `bearer` 并填写。
- Laya `max_len` / `head_max_len` 留空或 null 时不加入请求，沿用服务端默认值；填写时必须为正整数。没有新增拒答阈值。
- **新配置文件不存在**时，兼容原用户级 Jev 配置；首次保存 profile 可复制已配置的 legacy Jev，但不改写旧凭据。`config jev` CLI 保留为 legacy 管理入口；新文件一旦存在，应通过判断模型 TUI 管理 active profile。
- 判断模型 TUI 支持删除配置及其 Key；删除当前配置后不自动选择另一个目的地，而是保留 `activeProfile: null` 的显式停用文件（即使配置为空），避免旧凭据复活。删除非当前配置不影响当前目的地；取消与 dry-run 不写文件。已开始的运行继续使用原冻结配置；停止它须显式取消。
- `config jev --clear` **只清理旧 `keys.json`**，不会清理 `judgment.json` 中复制的 Key，命令会提示此边界。要清理本地存储的某个 Key，请在判断模型 TUI 中删除每个持有该 Key 的配置，并按需清理旧凭据。服务端吊销 Key 仍须在对应提供方控制台操作。
- 新文件损坏、模型不支持或认证配置非法时明确不可用，不回退旧凭据、不自动改写坏文件。请备份并修复该用户级文件。
- `search-boost status` / TUI 状态显示当前 profile/provider/model/transport、真实端点及 Laya 证据状态，不显示无关的 legacy Key。配置就绪不等于联网、容量或模型质量已验证。
- 公开工具 OFF 仍阻止新调用及工具内分页/恢复；profile 就绪不会覆盖已有 OFF 偏好。CLI `research list` / `research export` 仍可离线使用。

## 3. Laya 必须完整可判，不是 HTTP 200 就通过

对应已检查的 Laya **0.3.26**，源码 revision `2e4d9c87e8b1621deb344eac7de5c7258f32f849`。

需要真实 `routing.model` / `routing.repo` 及完整 usage 诊断：`state_tokens`、`state_tokens_dropped`、`truncated`、`truncated_questions`。strict 投影隐藏这些字段时，判断不可用。顶层泛称 `laya-rl-agent` 不能证明实际 checkpoint。

以下情况排除相关答案，不把残存 choice 当作通过、低价值或材料不存在：

| 情况 | 不可用原因 |
| --- | --- |
| 路由模型不明或与选择不同 | `routing_unavailable` / `model_mismatch` |
| usage 缺失或相互矛盾 | `diagnostics_unavailable` |
| 指定题目状态输入被截断 | `state_truncated` |
| 选项诊断报告不可区分 | `options_collapsed` |
| `abstention=abstained` 或 `low_confidence=true` | `abstained` |
| `abstention=unevaluated` | `abstention_unevaluated` |
| 缺少完整题头的离线证据 | `head_capacity_unverified` |

同一响应中的有效兄弟答案可以保留；缺失 safety 永不视为 clear，缺失 value 永不视为已建立。真实长中文材料按同样规则处理，不能通过删掉材料、缩短固定规则或改写选项来掩盖容量不足。

### 离线题头容量证据

证据文件为 `$SEARCH_BOOST_HOME/config/judgment-capacity/<profileId>.json`。它是部署者提供的**数据**，不是可执行 tokenizer、字符估算、在线 token 预检或模型调用。SearchBoost 不生成虚假的通过证据；本版本不附自动容量 manifest 生成器。

部署者应在其已有、固定版本的 Laya/tokenizer 环境中离线测量：

1. 核实实际部署的 Laya 源码 revision、checkpoint repo、model/tokenizer 不可变 revision（40–64 位十六进制）及有效 `max_len` / `head_max_len`。改变任一项须重新测量；HTTP 的 repo/model 名本身不能远程证明 revision，因此这些 pin 依赖部署者的可信配置。
2. 使用 SearchBoost 代码实际生成的题目，不另写简化题目。策略来自 `buildStrategyRequest`，筛选来自 `buildScreeningRequest`（`lib/search/screening/judgments.js`）；ranking preset 描述来自 `RANKING_PRESETS`（`run.js`）。索引、来源折扣 policy 和用户 preference 会改变具体题头；证据必须覆盖实际题目，不能拿短占位题代替。
3. 用同一 tokenizer 测量完整指令和每个选项，再调用该 revision 的 `laya.common.build_head` 测量实际保留的 token 序列。完整与保留序列应逐 token 相等，不能只比较相近长度。上游每个选项最多保留 48 tokens，拥挤时还会再次缩短；超出完整保留能力的题目不应写入通过证据。
4. key 使用 `headFingerprint(question)`（`lib/judgment/capacity.mjs`），即对按此顺序构造的 `JSON.stringify({type, instructions, criteria})` 做 UTF-8 SHA-256。必须沿用 JS 的字段与选项顺序，不能排序 criteria 或使用不同 JSON 空格。NOUL 题若显式指定 `labels`，还须在 criteria 后加入原样 `labels` 对象；标签改变会使原证据失效。客户端只接受 `type` / `instructions` / `criteria` 及 NOUL 的 `labels`，拒绝未知题目字段，以免未绑定的题头内容影响容量。
5. 将测量结果保存为下面格式。数值与 revision 必须来自真实测量，下面仅描述字段，不是可直接启用的 fixture。每题 `headTokens` 必须不超过 `headMaxLen`；完整与保留的指令数量相等；每个完整选项 ≤48 tokens，且与保留数量相等。还应离线确认 token 内容和选项可区分，而不仅是数量。

```text
version: 1
baseUrl: 与 profile 相同的规范化 API 前缀
model: 显式选择的 Laya 模型
layaVersion: "0.3.26"
sourceRevision: "2e4d9c87e8b1621deb344eac7de5c7258f32f849"
repo: 与服务 routing.repo 相同
modelRevision / tokenizerRevision: 实际部署的不可变 revision
maxLen / headMaxLen: 实际有效的正整数预算，headMaxLen < maxLen
heads: {
  "<headFingerprint 的 SHA-256>": {
    headTokens: 实际题头长度（包括结构 token）,
    instructionsTokens: 完整指令长度,
    retainedInstructionsTokens: 实际保留指令长度,
    optionTokens: 按实际选项顺序的完整长度数组,
    retainedOptionTokens: 按相同顺序的保留长度数组
  }
}
```

证据状态有 `missing` / `unreadable` / `mismatch` / `loaded`。缺失或陈旧证据不会锁住 profile 编辑，但对应判断保持不可用；修复证据文件后新运行重新读取。`loaded` 只表示 manifest 绑定字段合法，不保证覆盖每道动态题或判断质量。服务小窗口可能使普通批次不可用，应由部署者判断容量是否支持，不允许因此改变 SearchBoost 固定业务规则。

## 4. 返回和历史兼容

新运行使用 **schema v6**，新增必填 `run.judgment`：`provider`、`requestedModel`、`resolvedModel`、`transport`、`adapterVersion`。实际身份未知时为 null，不编造 Jev，也不使用请求别名补造 `resolvedModel`；Vercel SDK 的请求 `modelId` 同样不充当服务报告的实际 checkpoint。旧 `run.jevModel` / 传输 `model` 仍保留兼容别名回退，与权威身份分开。`run.community.source` 为 `judge` 或 `explicit`。`run.jevModel`、`usage.jev*` 与既有 `run.limits.jev*` 仅为兼容字段名，不足以识别实际提供方。

新分页为 `s6:`；显式保存写 `search-boost-research-v3` / schema 6。旧 v2/schema 5 按原合同和 `s5:` 读取，旧 v1 使用原只读历史分支与 `h1:`。读取均不重新判断、升级文件、改变原日期或冒充最新证据；旧记录不补造 `run.judgment`。输出 union 接受 v6、原 v5 和 v1 历史分支，MCP / Pi / DSH 共用同一合同。

## 5. 验证边界

`npm run test:judgment` 提供 12 组适配离线回归及 8 组发布审查回归（包含 Vercel SDK 离线身份、落盘与恢复、配置删除及 NOUL 标签指纹），覆盖注册、真实身份、可选认证、原文与固定题目、容量、截断/坍缩/弃答、重试/取消、配置冻结、不回退、历史只读与 TUI。完整发布门禁仍是 `npm run test:isolation`、`npm run check`、`npm run check:ci` 和需要 registry 访问的 `npm run audit:dependencies`。

离线 fixture **不证明**真实 Laya 部署已提供容量证据、线上语义准确率、语言能力、性能、成本或研究完成度。此次实现没有连接真实模型服务、安装模型或执行发布。有关 N_off 业务合同见 [单流程筛选合同](jev-adaptive-search.md)。
