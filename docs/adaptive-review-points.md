# Adaptive 后续审查点

用于保存讨论结论及实施对照。用户已要求安排顺序并实施；本轮按 **第三点 → 第四点 → 第二点 → 第一点** 完成核心实现。下文“记录时”段落保留原问题背景，当前行为以[当前契约](jev-adaptive-search.md)为准。

## 第一个点：查询选择与引擎选择尚未形成完整的反馈闭环

**状态：已实现；离线回归及两路独立源代码审查已完成，线上效果尚未校准。**

### 记录时的真实逻辑

1. 代码构造查询候选，主要是“完整问题＋研究点”，并提供带完整硬限制提示及不带提示的替代查询。intent提供给Jev理解，不直接拼入引擎查询。
2. 首轮在同一次Jev请求里分别询问：
   - 从已有查询候选中选择哪条；只有一个候选时不询问。
   - 当前允许的各个引擎是否适合研究任务。
3. 查询与引擎是共享上下文的独立判断，不是先确定查询、再针对该查询评估引擎。
4. 后续轮次由代码围绕未关闭的研究点构造候选，按固定顺序找未执行的“查询×深度×引擎”组合。沿用已有引擎权重，并检查健康状态、权限和重复调用。
5. 整体终检可以指定继续研究哪个点，但后续搜索不会每轮重新让Jev选择最佳查询或重新评估引擎。

### 当时指出的问题

- **候选质量受模板限制：** Jev只能在已有候选中选择，不能弥补候选缺少合适表达的问题。当前不是自由生成查询。
- **查询与引擎未建立明确依赖：** 适合整个研究任务的引擎，不一定最适合最终选中的具体查询。
- **续搜缺少反馈驱动的规划：** 固定遍历未执行组合可以推进搜索，但不等于根据当前缺口、已获得材料和检索反馈选择最有价值的下一步。
- **查询Choice接受规则不一致：** `chosenQuery()`仍使用`confidence >= 0.5`，没有采用终检已使用的完整有效选项分布校验。confidence缺失或偏低时，即使选项概率明确，也会回退到第一个候选。这是上一轮自审遗漏的问题。

### 用户确认的设计方向

```text
当前问题、研究目的与具体缺口
  → 构造有针对性的查询候选
  → Jev选择查询
  → 针对选定查询判断合适引擎
  → 执行并收集材料
  → 根据检索反馈更新缺口与下一次规划
```

需要同时设计预算与复用：只在确实要发起新搜索时规划；仍适用的引擎/查询判断可以复用，避免每个内部步骤都多调用Jev。具体协议、候选生成方式与阈值需要后续确认，不能直接把“自由生成查询”视为现有类型接口已经支持的能力。

### 后续验收关注

- 区分研究问题不变与搜索表达可变化，不擅自扩大研究范围或放宽限制。
- 引擎选择应明确对应将要执行的查询或查询策略。
- 续搜应实际使用当前缺口、已执行动作及检索反馈，而不是只换一个固定顺序中的候选。
- 查询判断应明确处理可选confidence缺失、无效分布、矛盾选项和回退行为。
- 新规划请求计入既有预算，遵守权限、健康检查、重复动作限制，不能以优化为由无限追加调用。

## 第二个点：终审根据当前全部入库材料判断是否满足问题与方向

**状态：已实现；离线回归及两路独立源代码审查已完成，线上效果尚未校准。**

### 记录时的问题

`lib/search/adaptive/retrieval-final.js` 的终检规则直接要求检查 `missing connections across points`，关键词续搜选项也提到 `unresolved connection`。措辞未明确限定为原问题本来就要求研究的联系，可能诱导模型自行扩展缺口，导致过度续搜。

### 应区分的两种情况

- **多方面资料收集：** 例如了解数据库的部署方法、授权限制、运行成本。各点有有用材料即可，不应额外要求建立“部署与授权的联系”。综合材料是主Agent的工作。
- **原问题明确研究关系：** 例如“某种缓存机制为什么导致一致性异常”。只有分别介绍缓存和异常的材料，可能仍缺少针对原题关系的材料或具体线索，此时补查有意义。但不要求Jev自己证明因果或完成推理闭环。

### 用户明确的终审定义

> 终审根据当前所有入库材料，判断是否满足问题和方向；不再检查限制词，因为入库前已经筛过。正常判断只有两种结果：通过；不通过，并判断哪个关键词需要重新搜索。

- **材料范围：** 当前全部有效的已准入材料，不是所有搜索候选，也不包含被拒绝、未完成准入或判断已失效的材料。不能以每点分数最高的几份代表摘录替代全部入库材料。
- **判断依据：** 原问题与研究方向（intent；省略时按原问题）。判断整组材料是否满足这次研究需求，不再仅以“有一批值得读的材料”或“再搜索是否划算”替代满足性判断。
- **职责边界：** 不重新判定constraints，不增加新的限制，不默认要求各点相互联系。原题明确要求研究某种关系时，按原题审查相关材料即可，不另设泛化的跨点联系门槛。
- **正常输出：** 通过；或者不通过＋一个已有关键词标识。两者是两类语义结果，不因关键词候选数量而改变。
- **不通过后的动作：** 围绕指定关键词重新搜索；新材料重新经过前筛与质量准入，更新材料库后，再基于当前全部有效入库材料终审。不能用其他点的新材料或重复材料自动清除未通过状态。
- **通过的含义：** 当前材料集在模型判断下满足问题与方向；不表示主Agent的最终答案已生成，也不是真实性或全网穷尽的认证。

```text
原问题＋研究方向＋当前全部有效入库材料
  → 终审（不重审constraints）
      → 通过：返回
      → 不通过＋已有关键词：针对该点重新搜索
          → 新材料前筛与质量准入 → 更新材料库 → 再次终审
```

### 后续验收关注

- 终审必须覆盖全部有效入库材料，不能把固定每点前三份材料的审查声称为全量审查。
- 若全量材料超过单请求预算，需要另行设计保留全量覆盖和整体判断能力的处理方式；不能默默截断或以简单分批投票冒充全局判断。尚未完成审查应披露为执行未完成，而非伪造通过。
- 不通过必须指定输入中已有的有效关键词，不能只返回不通过而不给续搜目标，也不能自行新增关键词。
- 超时、服务失败、响应非法或无法取得有效判断属于执行异常，不作为第三种正常终审结论，也不能强行映射成通过或捏造某个关键词。
- 资料收集型问题不因为各点材料彼此独立而被强行续搜；关系型问题不退化为只检查各关键词是否有结果。
- 终审不新增研究任务、不替主Agent撰写答案，不要求模型自己完成证明或论证闭环。
- 更新终审规则、返回协议、关键词续搜调度、材料版本及全量输入机制，以及对应测试、文档和桌面HTML；不能只改提示词。

## 第三个点：前筛只检查明确constraints，简化为通过／未通过

**状态：已实现；离线回归及两路独立源代码审查已完成，线上效果尚未校准。**

### 职责调整

- 移除前筛中独立的主体身份判断，材料是否与正确对象及问题相关，由后续相关性判断负责。
- 移除前筛对问题内隐含硬条件的单独提取与判断。所有需要强制执行的文档条件，由调用方显式放入constraints；不能依赖工具暗中补猜。
- 前筛只判断材料是否满足constraints中的全部完整条件。完整问题仍作为理解条件的上下文，确保主体、版本、日期等正确绑定，而不是新增一道主体门槛。
- 研究目的是否匹配仍由后续方向判断负责，不将意图或软偏好变成前筛硬条件。

### 用户确认的判定简化方向

```text
constraints为空
  → 跳过限制前筛

constraints非空
  → 结合完整问题，判断当前材料是否有足够依据确认满足全部条件
      → 通过：进入后续相关性、阅读价值与方向判断
      → 未通过：不进入本次正式材料集
```

- 不再需要pass/fail/unknown/not_applicable四个模型选项。
- 可用一个noul问题判断整组条件，由代码按门槛映射为通过／未通过；not_applicable不再必要，空条件直接跳过。
- 信息不足不能默认通过；“未通过”表示未建立准入依据，不一定意味着已经证实客观违反。
- 超时、响应缺失、非法数值等属于执行错误，不伪装成正常否定判断。二元准入动作不等于抹掉错误诊断。
- 所有条件按AND理解，不采用字面限制词命中、多数通过或平均分补偿。完整保留条件内部的否定、OR、例外和多主体绑定。

建议判断题：

> 结合完整研究问题，当前材料是否有足够依据确认满足constraints中的全部条件？必须保留条件中的否定、或者、例外与主体绑定；不能凭缺失信息推定符合。

### 补读与验证边界

- 摘要没有给出某项必要信息时，也可能未通过；不代表全文一定不符合。
- 是否补读全文，应作为独立、受预算约束的检索策略设计，不依赖四选项前筛承担全部恢复职责。
- 一次整组判断比逐条判断更简洁，但逐条可审计性下降，可能漏看某个条件；不能宣称它与逐条判断再AND天然等价。
- 整组判断的数值含义与原逐条判断不同，门槛及漏判情况需要验证，不能仅因复用原数值就声称效果等价。

### 后续验收关注

- 空constraints不产生限制判断请求；非空时仍先完成前筛，再进行质量判断。
- 不额外创建主体条件或从问题重新提取一套隐藏限制。
- 通过条件不能借用同页其他主体的版本、平台或日期；不是词面匹配。
- 任一未建立的必要条件不能被其他条件高分抵消，信息不足和执行失败均不能默认准入。
- 用否定、OR、例外、多主体、缺少证据等案例验证整组判定，明确正常未通过与调用失败的区别。
- 同步调整未知恢复策略、状态与诊断、请求预算、测试、公开字段说明和桌面HTML；不要只删两个选项而保留互相矛盾的旧逻辑。

### 主要涉及位置

- `lib/search/adaptive/scope.js` — 现有主体/隐含条件/逐条限制的四选项判断。
- `lib/search/adaptive/loop.mjs` — 前筛分流、补读恢复、质量调度、版本失效与诊断。
- `lib/search/adaptive/input.js`、`prompts.js` — 明确限制的输入契约和相关性职责。
- `docs/jev-adaptive-search.md`、桌面HTML — 对应流程解释。

## 第四个点：宽准入、重点排序，保留中等价值的有用材料

**状态：已实现；离线回归及两路独立源代码审查已完成，线上效果尚未校准。**

### 用户目标

> 尽量突出重点，而不是只保留重点。避免多道重叠门槛误伤中等价值网页，也不要出现收集了大量候选却只留下极少材料、又无法解释损失发生在哪一步的情况。

调整方向是较高召回的有用材料收集：明确无用的排除，中等价值的保留，高价值的突出。不是无条件增加返回数量，也不是保证搜索200个就必须返回某个固定数量或比例。

### 记录时的问题

- 限制、相关性、阅读价值、方向、关键词匹配连续门控，部分职责重叠，可能把“不够直接命中重点”误当成“没有保留价值”。
- 方向提示对泛化背景的排斥，需要区分有帮助的背景与无关的泛泛介绍。
- 单纯下调几个数值，不能解决提示语义和多重否决带来的误伤。
- 当前可以在部分候选尚未审查时提前结束。收集200个、只返回8个，既可能是筛选过严，也可能是只审查了其中30个；两者不能混为一谈。

### 用户确认的设计方向

1. **保留硬边界：** 显式constraints必须满足，不允许高价值分抵消不符合条件；注入与网络安全独立保留，不为增加结果数量而削弱。
2. **放宽价值准入：** 排除明显无关、纯广告、无实质内容的材料，而不是只保留非常有用或最直接的材料。有实际帮助的背景、局部解释、具体线索和间接证据可以保留。
3. **方向主要用于排序：** 强调研究重点，但不因材料属于有用补充而一票否决；真正无助于原问题的跑题材料仍应排除。
4. **关键词用于贡献归属：** 用于判断材料帮助哪个点、贡献多少，不宜同时充当过强的整篇网页删除门槛。材料被保留，不等于自动给某点记账或使该点满足。
5. **区分重点与补充：** 重点材料优先展示，补充材料靠后但保留；两层都经过相应准入与硬限制检查，不把未审查候选冒充合格补充材料。本轮具体采用focus/supporting展示分层。
6. **检查审查覆盖与停止策略：** 不只调整阈值，还要评估是否过早停止、是否给有希望的候选足够审查机会；仍遵守有限预算，不要求无限审完所有候选。

判断语义应围绕：

> 这篇材料是否对理解原问题有实际帮助？它是直接帮助，还是补充帮助？

“是否直接命中重点”不能等同于“是否值得保留”。例如研究失败案例时，一份解释故障机制所必需的架构说明可以作为补充材料，不应仅因没有直接列举失败案例而被删除。

### 与前面审查点的衔接

- 第三点的constraints前筛继续承担明确硬条件，不因本点放宽价值准入而变成软偏好。
- 第二点的终审仍以原问题、方向和当前全部有效入库材料判断是否满足；重点与补充材料均属于有效材料时，均纳入终审范围。
- 不用宽松准入虚增关键词完成情况，不用固定返回量代替终审，不自动增加研究任务。

### 后续验收关注

- 用直接高价值、中等价值背景、局部信息、具体线索、间接证据、反证，以及明显无用材料组成对照案例，验证有用补充材料的保留与排序。
- 明确各门槛、提示词和公式的职责，减少重复否决；新的数值门槛需验证，不凭直觉宣称降低数字就改善了召回。
- 分别统计收集量、URL去重后候选量、实际审查量、硬限制未通过量、价值筛选未通过量、已准入量和尚未审查量，区分未通过、待审和执行异常。
- 审查补充材料能否进入结果及全量终审，同时不会虚假填满关键词进度。
- 评估候选审查覆盖、提前停止和预算分配，不能把未审查材料记作不合格，也不能为凑数量降低硬条件要求。
- 同步修改准入与排序逻辑、关键词贡献、终审输入、诊断、测试和说明文档；记录真实样本上的误拒、污染与成本，不承诺固定通过率。
