## 保存 Key：有没有白名单，结果不同

- **已有 `enabledEngines` 白名单：** 保存 Key 不改这份额名单。新 Key 不会因此进入默认搜索。
- **没有白名单：** 保存 Key 会让这把 Key 进入默认搜索。已启用的付费 API 可能产生费用，以服务商现行规则为准。这是 0.3.0「已配置即启用」的规则，不是第二条搜索协议。
- **不要让刚保存的 Key 进入默认搜索：** `search-boost config keys --disable <id>`，或 `search-boost config keys --engines <id>[,<id>]` 写成只含所选引擎的显式白名单。

`deepseek-search` 仍是原来的 ID。启用后只调用官方 Search API，不会同时调用旧的 messages/web_search。

## 安装、升级、回滚

安装本次交付的 tarball。把路径换成你保存文件的位置：

```sh
npm install -g /absolute/path/to/search-boost-0.3.1-beta.1.tgz
search-boost --version
```

`search-boost --version` 应打印 `0.3.1-beta.1`。已有 0.3.0 的 Key 和白名单会保留。

升级软件包后，对已安装的宿主接入执行：

```sh
search-boost refresh -y
```

`refresh` 只刷新当前包的接入，不自己升级 npm 包。

回到 0.3.0：

```sh
npm install -g search-boost@0.3.0
search-boost refresh -y
```

0.3.0 会再次使用当时的 messages/web_search 协议。白名单本身不需要为回滚改格式。若把 Base URL 留在 Search API 的源站，回到 0.3.0 后会按旧路径拼接，应在回滚后恢复该引擎的默认 Base URL。

## 协议变化

- 旧：`POST https://api.deepseek.com/anthropic/v1/messages`，模型 `deepseek-v4-flash`，工具 `web_search_20250305`。
- 新：`POST https://api.deepseek.com/v1/tools/search`。没有模型消息，没有 web_search 工具，没有自动 Fetch。
- 文件里若仍是旧的默认基址 `https://api.deepseek.com/anthropic/v1`，会当作旧默认值，只请求新的 Search 端点。
- 自定义基址若路径含 `/anthropic` 或以 `/messages` 结尾，请求不会发出，并提示恢复默认 Search 基址。
