# SearchBoost 0.3.1-beta.2

版本：`0.3.1-beta.2`。这是同一分支上的下一轮候选，不是稳定版，也没有 `npm publish`。registry 上没有这个版本。不要执行 `npm install -g search-boost@beta` 或 `npm install -g search-boost@0.3.1-beta.2`。

上一轮对照只锁定 `cc49eee` / tree `bc964ee9` / tarball `73906b87…`。`37077ba` 是 NO-GO，只作历史反例。协议仍是官方 `POST /v1/tools/search`。没有 live 账号验证，费用保持 NOT RUN。

beta.1 没有跑完键盘、中文窄屏、`NO_COLOR`、非 TTY、取消不写和配置冲突，所以这一轮不继承界面通过。界面证据来自 `scripts/test-v031-beta2-ui.mjs`。

安装这一轮候选：

```bash
npm install -g /absolute/path/to/search-boost-0.3.1-beta.2.tgz
search-boost --version   # 必须打印 0.3.1-beta.2
```

## 这一轮改了什么

- 只点名一家不可用的 API、又没传 `engine_pool` 时，结果里的 `enginePool` 改成这家引擎所属的池。DeepSeek 缺 Key 时是 `api`，并写明这个池没有运行。不再把自动标签 `free` 显示成已经搜索过免 Key 池。
- 缺 Key 的错误分成完整句子，并给出下一步：`search-boost config keys --show`，然后 `--set` 与 `--enable`。仅本次免 Key 仍是 `engine_pool=free` 且不要列出 Key 引擎。
- `engineStats` 的 note 仍最长 120 个字符。超长时保留开头和结尾，不再只留开头。
- 搜索默认页把协议放在第一行，并按界面语言只显示一种语言。第一屏能看见 `POST /v1/tools/search`，不必翻过中英对照。
- `Retry-After: 1.5` 按 1.5 秒解释。超过 1 秒预算就停止，不再交给 `Date.parse`（那会得到 2001-01-05 并立刻重试）。`0.5` 仍会等待 500ms 并继续，直到次数预算用尽。
