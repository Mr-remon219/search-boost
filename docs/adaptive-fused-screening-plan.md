## 一、如何使用本规范

本文区分三类内容：

| 类别 | 约束程度 |
|---|---|
| 设计契约与不变量 | 实现必须遵守；改变职责、信号含义或安全边界属于设计变更，应明确说明并确认 |
| 数学模型与可校准参数 | 公式和各项语义明确；参数在给定合法域内依据证据校准，版本化记录，不以示例值作为永久默认值 |
| 示例及实现参考 | 用于解释，不规定目录、文件拆分、开发顺序、批量、并发、工具调用编排或调参步骤 |

执行者应结合现有代码、测试与实验结果安排工作。可以调整模块边界、工作顺序、批次大小、并行方式、实验规模及算法的等价实现；不得借此改变产品职责、绕过硬条件或隐去成本与未知状态。

**有证据支持下一步即可推进，不要求遵循固定阶段清单。未经收益和风险验证，不将实验方案直接替换默认路径。** 这是发布边界，不是要求某个文件必须先改的执行流程。

## 二、产品定位与职责边界

### 2.1 目标

**为主 Agent 提供经过限制检查、价值分级及偏好排序的网页，减少初筛工作。**

| 组件 | 负责 | 不负责 |
|---|---|---|
| fused | 召回、引擎路由、并行检索、URL 合并、基础融合分及列表多样性能力 | 证明网页事实真实或完成研究 |
| Jev | 从代码预设选项中选择 ranking、判断限制、价值档位、来源折扣和偏好匹配 | 自由生成查询、研究点、选项、数值系数或答案 |
| 代码 | 定义规则与预算、校验响应、计算分数、管理状态与缓存、输出结果 | 把缺失判断当作批准，把排序分当作真实性 |
| 主 Agent | 提出问题、阅读决定性证据、核验、推理、发现缺口并决定继续研究 | 把 5 档材料当作无需核验的事实 |

### 2.2 已确定的范围

- 取消目标架构中的 `keywords`、逐词进度与保底、自主查询规划、逐引擎 Jev 选择及全量终审。
- 问题与研究方向必填，使用英文；只使用问题作为搜索查询，不拼接方向、偏好或代码生成的后缀。
- Jev 选择的是 `balanced / research / fresh` **ranking 预设**，不是 `free / api / hybrid` 引擎池。
- 保留显式限制前筛、0–5 价值分级、独立来源偏置和独立偏好加分。
- 仅交付通过准入且价值为 3–5 档的材料，明确标注档位。
- 不维护跨网页“研究完成总分”。单 URL 总分用于排序，数量和预算用于终止候选处理。
- 工具内部处理不足的候选数量和判断依据，不替主 Agent 推进研究路线。

“单 URL 最终排序分”“交付数量达标”“研究已经充分”是三个不同概念，不得在输出中互换。

## 三、输入、输出与判断契约

### 3.1 输入语义

目标输入沿用现有 `questions` 单元素数组和 `intent / constraints`，增加可选 `preferences` 及交付数量 `max_results`。这是目标契约，不要求立即迁移公开接口。

| 输入 | 语义 |
|---|---|
| `questions` | 恰好一个英文问题；它定义本次检索对象，也是查询本身 |
| `intent` | 必填英文研究方向；说明需要什么材料，不自动成为文档硬限制 |
| `constraints` | 明确、完整、可核验的文档硬条件；数组项之间 AND，项内 OR、例外和否定不得丢失 |
| `preferences` | 调用方的软偏好；只影响合格材料的优先级，不是准入条件 |
| `max_results` | 本次最多交付的结果数量，不是单引擎数量、候选量或价值档位 |
| `page_size / cursor` | 分页展示与保存结果读取；不能把翻页当成新检索 |

问题与方向的英文要求不等于只收英文网页，不额外强制限制和偏好的语言。不能把“仅 ASCII”当作英文，也不能因为英文句子包含非拉丁专名或代码就机械拒绝。语言判断方法由实现选择，须覆盖边界案例；不能静默改写或翻译后冒充原查询。

具体长度、数量和时间上限由版本化输入契约与运行时预算声明，本规范不指定永久默认值。与既有字段不兼容的改变须显式迁移，不静默截断或解释旧输入。

### 3.2 Jev 的选项边界

所有选项、适用标准和响应 ID 均由代码提供。Jev 只能选择，不自行生成选项、数值系数或自由文字依据。Choice 概率可用于验证选择及处理不确定性，不直接作为材料价值或加分。

逻辑依赖是：原始检索观察支撑基础分和来源判断；约束前筛先于价值准入；有效准入与已建立的价值档位支撑最终发布。批处理、缓存复用及并发方式可由实现决定，但不能改变这些依赖或伪造通过状态。

### 3.3 Ranking 与权限

固定选项为 `balanced / research / fresh`，依据问题、方向、偏好及代码提供的能力说明选择。策略选择结果应在一次检索快照内保持一致并可追溯，不因候选得分不理想而反复重选。

- ranking 只改现有引擎融合权重，不启用引擎、扩大池、修改凭据或绕过禁用状态。
- `fresh` 不自动构造日期条件或提升搜索深度。
- 无效选择可采用预先声明且明确披露的回退策略；不能把回退记录成模型认可。
- 输入不合法不能通过策略回退继续执行；策略选择失败也不等于材料审核完成。

### 3.4 限制审核与未知

限制非空时，只有全部明确条件获得足够依据才准入；为空则跳过，不从问题、方向或偏好中添加隐藏门槛。高价值、来源权重和偏好均不能补偿限制不满足。

状态至少要区分：已确立符合、明确冲突、证据不足、判断不可用。数值偏低或普通 non-pass 不能自动解释为已证实违规；未审查也不能解释为被否决。可用何种固定选项表达这些状态，由实现保持语义一致。

### 3.5 材料价值档位

| 档位 | 含义 | 可发布 |
|---|---|---|
| 0 | 不相关、无可用阅读价值 | 否 |
| 1 | 弱联系或泛泛提及 | 否 |
| 2 | 相关，但缺少足以优先交付的实质内容 | 否 |
| 3 | 中价值：实质背景、局部解释或可用线索 | 是，仍须通过其他准入条件 |
| 4 | 中高价值：直接服务问题与方向，提供较明确的依据或可追溯材料 | 是，仍须通过其他准入条件 |
| 5 | 高价值：优先值得打开，直接提供关键依据，并能定位原始来源、方法、测量条件或同等任务相关依据 | 是，仍须通过其他准入条件 |

无法建立档位是 `unestablished`，不是 0 档；响应缺失或非法属于执行不可用，不是低价值。

依据限于实际审查片段和可见元数据，不能仅因出现实验术语、数字表格或论文域名就给高档。高价值不要求一篇材料回答整个问题，也不要求所有任务都必须有论文或代码；反证同样可以高价值。

### 3.6 来源折扣：独立的政策偏置

**来源折扣是需要保留的独立项，不被价值分级或偏好加分替代。** 它依据真实检索来源，不是网页自称的渠道，也不是对网页真假作保证。

（原型把 none/mild/strong/unknown 的系数放在 `scoring.js` 的参数表中，政策对象只承载适用条件、允许集合与版本；`admitAndRank` 同时返回 `sourceBiasPolicyVersion` 与 `params.discountFactors`，产物仍可重建。）通常可用 `none / mild / strong / unknown` 表达；具体数字是可校准参数。Jev 只判断预设条件是否成立，不自行创造引擎声誉或引擎分组。

必要边界：

- 来源来自实际 `engines / engineRanks / provenance`，失败、未观察到或无有效贡献的引擎不充当支持。
- 同 URL 多引擎观察合并后选择一次折扣，不取最先返回的引擎，也不按命中次数连乘。
- 不符合代码允许条件的折扣选项不能生效；未知保持中性并披露，不捏造折扣依据。
- 增加一个真实检索来源，不应仅因为引擎数增加而受到更强折扣。
- 折扣改变排序贡献，不改变价值标签或准入状态。

偏置可以是有意的渠道偏好，也可以是经过验证的增量信号，两者必须区分。若刻意加强了 ranking 已有先验，应注明“政策偏置的重复强化”，不能宣称新增独立质量证据。只有独立验收支持时，才能声称它改善了质量。

本规范不虚构某个引擎天然较差的映射。没有已确认的具体映射时，采用 D=1 的中性对照；这不取消折扣机制。可用渠道白名单、允许折扣集合或等价的规则表实现，无需固定某种数据结构。

折扣选项的**适用条件**必须完整：eligible 集合只回答“允许选什么”，当 `none/mild/strong` 同时合法时还必须说明“何时应选哪一个”。政策若启用模型判断，必须同时提供 `none/mild/strong/unknown` 四档完整条件；部分覆盖在任何判断调用前报错，不与默认引擎集合条件拼接。适用性无法确立时选 `unknown`；已确立的条件若重叠，则在允许选项内按 `strong > mild > none` 选择，`none` 应描述无适用折扣的情况。这是明确的政策选择优先级，不是渠道质量结论，也不能用强折扣覆盖未知。条件文本的任务合理性仍需审核，结构校验和离线测试不证明真实模型遵循规则。若政策只列出允许的引擎集合而没有写明条件，则折扣档位由代码按该政策直接判定（`selection: 'code'`）。缺失来源仍只记 `unknown` 并中性披露。

### 3.7 偏好奖励：不可遗漏的独立项

对调用方每条偏好使用 `match / partial / no_match / unknown` 等固定选项判断，再由代码映射奖励。

- 无偏好时奖励严格为 0；未知和不匹配均不给奖励，但诊断中须区分。
- 偏好不匹配不等于材料低价值，不自动改变价值档位。
- 多条偏好使用有界聚合，不能靠增加条数无限堆分；精确重复应去重。
- “符合偏好”不能抵消硬条件、安全或价值准入失败。
- 赞同预期结论不自动意味着更高证据质量，反证仍可符合偏好。

偏好匹配、材料价值和来源折扣是三个不同判断，即使同一次批量请求取得，也不能合并成一个不可解释的等级。

### 3.8 输出语义

输出必须能够表达：

- URL、标题和实际审查摘录；不让 Jev 自由生成未经材料支持的事实摘要。
- 每条材料的 3/4/5 档位，以及最终入选顺序。
- 可追溯的基础分、价值效用、来源折扣、偏好奖励和排序策略版本。详细解释可以放诊断结构，不要求每次重复冗长文字。
- 请求数量、实际保存结果数、本页数量、是否够量、停止原因与未完成判断。
- 未审查、限制未确立、低价值过滤、服务不可用等不同计数；不能把事件次数当唯一文档数。

档位分组不能再次机械按 5→4→3 覆盖最终排序，否则独立折扣和偏好作用会被抹掉。4 档可以因其他因素排在 5 档之前，标签仍保持原意。

未通过限制、0–2 档、核心判断不可用的材料不进入正常结果；通过诊断披露数量与原因。5 档不是真实性认证，数量达标也不表示研究完成。

原型产物与公开 schema 可分开。正式迁移必须显式版本化，不把旧 `retrievalSufficient / convergence / keywordProgress / finalReview` 偷换成新的交付语义。旧 cursor 按原契约读取直到失效；分页不能触发网络或 Jev 调用。字段布局、schema 版本号和迁移技术由实现决定并验证兼容性。

## 四、排序数学模型与不变量

### 4.1 需要避免的旧问题

旧示例式 `S_old=B(VD+C)`，取 V=1/1.2/1.4、D=1/.9/.75、C∈[0,.1] 时，只能把 B 乘以 .75–1.50。基础分相差超过 2 倍时，后续判断无法逆转顺序。

目标不是“5 档永远第一”，而是**价值判断和偏好奖励不能仅因为 B 小就同步接近零**，同时保留基础排序的作用。旧式可以作为对照，不再作为推荐设计。

### 4.2 准入先于总分

对候选 i，发布资格为：

```text
A_i = 硬条件全部确立（或无条件）
      AND 通过文本有效性／注入风险检查
      AND 价值档位已建立且属于 {3,4,5}
      AND 实际 fused 基础分 B_i 有限且为正
```

只对 A_i=true 的材料计算正常发布排序。不能通过设一个很低的分数，让不合格材料在结果不足时重新出现。

### 4.3 信号定义与组合公式

| 符号 | 定义 |
|---|---|
| B_i | 原始 fused `score`，原样保留用于追溯 |
| b_i | 固定尺度变换 `B_i/(B_i+τ)`，τ>0 |
| u_i | 价值档位的代码效用映射，`0≤u(3)<u(4)<u(5)≤1` |
| D_i | 预设来源折扣的代码映射，`0<D_i≤1`；未知中性并披露 |
| p_i | 有界偏好匹配聚合，范围 [0,1]；无偏好为 0 |
| λ | 基础排序相对价值效用的权重，范围 [0,1] |
| ε | 偏好奖励上限，有限且非负 |

```text
b_i = B_i / (B_i + τ)
core_i = λ × b_i + (1 − λ) × u_i
sourcePenalty_i = (1 − D_i) × core_i
preferenceBonus_i = ε × p_i

S_i = core_i − sourcePenalty_i + preferenceBonus_i
    = D_i × [λ × b_i + (1 − λ) × u_i] + ε × p_i
```

来源折扣作用于基础与价值的组合分，偏好奖励独立相加；两者均不修改 A_i 或价值标签。Jev 选择类别，代码决定效用和系数，不能把 Choice 概率直接代入 u 或 p。

τ 是与 fused 评分版本绑定的参考尺度，不按每次候选池重新拟合。使用固定尺度而非当前列表 min-max 或百分位，避免加入无关网页就改变其他条目的分数。评分尺度变更须迁移 τ、升级策略版本并处理缓存。

偏好聚合可采用去重后匹配值的等权平均；若使用固定正权重，须归一化并说明含义。具体匹配效用和权重需要校准，不由 Jev 自由给出。

### 4.4 排序逆转与模型局限

在 D 相同、偏好相同时，低 B 的高价值材料 h 超过材料 l，当且仅当：

```text
(1 − λ) × [u_h − u_l] > λ × [b_l − b_h]
```

价值差的贡献是 `D(1−λ)Δu`，偏好差的贡献是 `εΔp`，均不再乘原始 B。一般情况直接展开 S_h−S_l，不使用隐藏的“高档必胜”规则。

这赋予 Jev 实际重排空间，但不证明新模型一定更好：压缩 B 会损失幅度信息，误分档可能被放大，渠道偏置可能与基础先验重复。效用表的间距是排序政策，不是价值等级天然可测的距离。必须通过外部评价验证。

### 4.5 数学与实现不变量

在准入状态及其他信号固定时：

- S 对 B 单调不减；λ>0 时数学导数为 `Dλτ/(B+τ)^2 > 0`。
- S 对 u、p 单调不减；无偏好奖励为 0；更强折扣不增加 S。
- `0≤S≤1+ε`。S 可能超过 1，不是概率、正确率或可信度百分比。
- 重复来源不重复施加 D，多写偏好不无限增加奖励。
- 其他候选的加入不改变本条 S，除非本条材料或其真实来源观察也发生变化；最终列表仍可因竞争和多样性改变。
- 固定判断结果与策略后，代码分数可确定性重放；不保证重复调用 Jev 得到完全相同的类别。
- 同时按正比例缩放 B、τ，数学上 b 不变；λ=1、D=1、ε=0 且关闭多样性修正时，与 B 的顺序等价。
- 极端浮点输入不得产生溢出导致的错误反转或 NaN；有限精度下允许饱和和并列，但排序须稳定，不依赖网络返回顺序。

采用数值等价的稳定实现即可，不规定具体代码写法。参数必须版本化，并能重建每条结果的贡献项。

### 4.6 列表选择不等于单条质量分

如果加入多样性修正，应保留与 S 分开的列表选择分，例如：

```text
selectionScore_i = S_i − μ × redundancy_i
```

其中 μ≥0，redundancy 是与已入选条目的有界相似度。可使用现有算法或有证据支持的等价实现，但不能直接把旧 fused 尺度下的 .15 系数搬到新尺度上。

原型已按此实现：`finalScore` 保持不可变，逐轮以“与已入选条目的最大有界相似度”重新计算 `selectionScore`；`mu=0` 时退化为按 `finalScore` 排序。相似度是词面近似（标题＋正文三元组），只用于软降权，不作为文档身份判断。

URL 去重、文本近似重复、同论文多入口与跨语言译文不是同一种身份判断。折叠策略需要验证，不能把词面相似度宣称为可靠语义去重。最终名次与价值标签分别输出，不覆盖原始分。原型默认关闭折叠：跨域名共享 slug 与标题的独立页会被启发式合并，在留出集负例验证前不作为默认行为。

## 五、候选、补读与资源约束

### 5.1 “没搜够”的含义

交付不足可以触发对尚未处理候选的处理，不触发自主研究规划。相同查询、相同参数、相同缓存结果不能被算作新增进展。

一次融合候选快照通常足以承载初始原型。若使用提供商真实支持的分页或补量能力，须有可核验的新候选、明确预算且不扩写研究问题；不能假定适配器具备尚未验证的能力。

候选数、批量、补量时机、并发与提前交付方式由执行者根据收益和成本选择。运行时必须有明确的调用、材料、字节/token、重试和截止时间边界；上限不是必须消耗的工作量。

足量、池耗尽、无新增材料、取消或预算耗尽均可结束处理，返回实际结果及原因。未审查项保持未审查，不能被描述为低价值。输出最多声称“已审查候选中的优先结果”，不是全网最佳。

### 5.2 有限补读的安全边界

严格前筛可能因摘录缺少实验条件而漏掉真实合格材料。允许以独立、有限预算补充当前候选的判断依据，但不能放宽限制或恢复研究循环。

补读须满足：

- 对象来自真实候选池，有与任务相关的可见线索，现有依据不足；不是让 Jev 生成新 URL 或无限追踪引用。
- 明确冲突、无关或安全阻止与信息不足分开处理；低 Boolean 分不能直接等同违规。
- 每个规范化候选最多补读一次；网络层受既有重试与重定向安全策略约束，不能借补读反复洗白。
- 文本通过 MIME、二进制和长度保护；新文本版本重新检查限制，旧批准不能自动继承。
- 仍未知或读取失败时不发布；不能因发生过补读就给价值加分。
- 读取与重新判断计入总费用和总截止时间，不隐式延长宿主预算。

是否启用、选择多少候选、怎样安排读取和判断，由实验与实际预算决定。本规范不指定必须补读几页、消耗几秒或使用哪种请求编排。

默认的初始范围只有“条件信息不足”。可选扩展允许**条件已通过、价值仍未确立**的候选各补读一次（显式开关）；候选按真实基础分排序，仍受同一规范化 URL、有界次数、新文本版本重新检查、失败或仍未确立时不发布等全部约束。该扩展不是默认行为，其净收益需按第七节独立测量。

### 5.3 不能只评价被返回的材料

验收需覆盖被前筛挡下的候选，独立核对是否真的不合格，特别记录 `snippet_insufficiency_miss`：实际满足条件却因摘录不足被排除。

补读开关的效果应包括恢复的好材料、额外误收和成本。没有开启补读也不能省略摘录不足漏收的测量。未读到正文、未审查或独立审核无法判定的项目保持未知，不被统计为真实不合格。

## 六、缓存、故障与兼容性

### 6.1 缓存的语义绑定

同一 URL 或文本未变，不代表对不同问题仍有相同价值。判定缓存必须覆盖影响该判断的输入：

```text
question + intent
+ 实际审查文本／片段选择版本 + 相关元数据
+ constraints + preferences
+ Jev 模型／请求模板版本 + 判断策略版本
```

来源折扣另绑定 ranking、逻辑引擎集合、原始排名、provenance 与 sourceBiasPolicy。分数计算绑定 B、fusion scoreVersion、τ/λ/u/D/ε；列表选择还绑定候选集、去重/多样性策略及其参数。保存结果需反映实际审查范围、预算和补读状态。

实现可以分层缓存并缩小各阶段的键，但须能说明哪些字段确实无关，不能默认忽略 question/intent。fused 检索缓存与 Jev 判断缓存语义分离，旧策略结果不能伪装成新策略结果。

### 6.2 失败不得改写成成功

- 未知、正常否定、未执行、无效响应和服务故障分别披露。
- Jev 不可用时不能把未审核 fused 结果标为已筛选；可返回明确不可用状态，由主 Agent 决定另用 fused。
- 预算退出可保留已有效筛选的部分结果，不降低条件或价值门槛凑数。
- 网页是证据，不得生成新约束、偏好、选项或系统指令。
- PDF 二进制、乱码及不受控正文不能作为成功文本进入 Jev 或主 Agent 上下文。共享读取故障与重排质量分开归因、修复和评估。

原型另外记录以下工程行为：批量按序列化请求上限打包（条数只是上限），单条仍超限时不发送并以 `request_too_large` 披露；**补读请求走同一尺寸检查**，超限不派发并保留补读前的文本与判断；判断批次失败时保留已取得的判断，未取得者标为 `judgement_unavailable`；**已派发但未取得可用评估的候选使运行标记为未完成**（停止原因归为 `unassessable_material`，而不是“池耗尽”）；初始候选的非 `clear` 安全状态不发送判断；已取消的 signal 不发起外部调用。读取或判断返回、抛错以及最终输出时都检查停止状态，避免末次操作漏报取消或超时；已有有效结果保留，中断时 `incomplete=true`。数量已达标时可以保留 `stopReason=target_met`，但 `run.halted` 独立披露中断原因。这不表示能主动终止在途调用。评分参数和结果数量须在外部调用前验证，非法配置不消耗读取或判断调用。

### 6.3 兼容与发布边界

试验不能静默改变现有 fused 或 adaptive 的默认行为、权限及公开契约。默认路径迁移要有明确批准、版本和回滚边界，不能因为公式性质测试通过就直接切换。

共享实现、宿主字段一致性、旧 cursor 和缓存隔离需要验证。目录划分、具体文件改动、兼容层写法及是否分多个补丁，由执行者判断；本文不规定实施顺序。

## 七、验收证据与判断标准

本节规定需要回答的问题，不规定必须依次执行的实验脚本。可以按证据调整探索顺序和规模，但不能遗漏关键归因、看完验收结果后再更换标准，或用自身分数作为真值。

### 7.1 工程与数学正确性

验证输入、固定选项、严格准入、未知状态、缓存失效、补读边界、预算退出、分页及跨宿主语义。数学实现应覆盖第四节性质、低 B 高价值的逆转例、4 档可超过 5 档、极端值和稳定重放。

保留现有融合、路由、适配器与网络安全回归，完成项目要求的验证。数学测试只证明规则被正确执行，不证明真实检索效果。

### 7.2 可归因的效果对照

比较排序规则时，应控制查询、候选池、实际审查文本、判断标签和其他处理，避免把额外召回或正文读取的收益归给公式。判断波动、ranking 选择、补读与多样性的作用分别评估。

下列对照关系需要有证据，分组顺序和具体实验工具不固定：

| 比较对象 | 要区分的贡献 |
|---|---|
| 原始 fused 与 fused + 仅限制检查 | 条件过滤本身的价值与误拒 |
| 仅限制检查与再加价值分档 | Jev 价值判断是否独立有益 |
| 同一价值准入集合按 B 排序与按新公式排序 | 筛掉低档材料和重新排序各自的作用 |
| H+V、H+V+D、H+V+P、H+V+D+P | 来源折扣与偏好是否各有增量，特别是完整系统去掉 D 后的变化 |
| 旧倍率式、新混合式、价值排序、基础分顺序等价回退 | 数学组合本身的收益与代价 |
| 同策略补读开启与关闭 | 信息不足漏收能否挽回、是否值得额外成本 |

H/V/D/P 分别表示限制、价值、来源折扣和偏好。原生 fused 最终列表作为产品参照；纯排序对照保持相同去重/多样性规则或关闭其额外修正，不混淆两个层面。

使用独立标签衡量首屏可用性、直接证据、限制误收/漏收、重复率及偏好符合度。纳入措辞贴题但出处不明的博客、摘要缺实验条件的合格论文、不贴词但关键的一手材料、反证和多入口重复。

调参与验收数据分开。记录真实 B 分布再选择尺度与权重，不无约束地同时拟合全部系数。具体参数扫描由证据决定，无需照抄附录数值。不同返回数量需同时报告质量、有效证据数量、池内召回与交付率，防止靠少返回来制造优势。

### 7.3 工作量与完整任务成本

比较实际审查量和补读量的边际收益，而不是把某个候选上限当固定工作量。额外审查也可能因误分档挤掉好结果，不假定结果随数量单调改善。

端到端比较需要控制主 Agent 模型、思考强度、任务和预算，并报告：

- 首屏证据可用性、关键证据到达时间、无效 URL 阅读和重复搜索。
- 限制误收、摘录不足漏收、补读恢复及尚无法判定的数量。
- 各工具阶段与完整任务耗时，内部引擎/Jev 请求、token/费用和主 Agent token/费用。
- 最终答案仍需纠正的事实问题；高档标签不能免除核验。
- 重复运行的差异与置信范围；不足以估计稳定 p95 等统计量时明确说明。

真实外部实验需在授权费用、时间和网络范围内执行。只减少内部请求或只减少主 Agent 思考，都不足以证明总成本下降。

### 7.4 默认路径替换的完成标准

在验收前明确任务风险下可接受的误收/漏收、首屏收益和完整成本变化。阈值可由开发证据和产品需求确定，不能在验收后为迁就结果临时更改。

至少应有证据支持：信息不足漏收可控；价值筛选/重排确实有用；主 Agent 节省的工作能够抵消新增判断成本。来源偏置若仅表达政策偏好，不得冒充已证实的质量增益。

结果不足、无收益或风险不能接受时，保留原型而不强推默认迁移。满足这些条件不意味着实现必须按某个固定阶段推进，也不替代必要的发布授权。

## 八、留给执行者的判断空间

可以根据代码与反馈自主决定：

- 模块和文件如何拆分、哪些已有函数值得复用、开发和验证顺序。
- 批处理、并发、候选获取方式及有界重试的具体实现。
- 在既定权限内的实际候选量、是否补读、补读对象及时间分配。
- 数学等价实现、合法域内的参数校准、来源规则表的具体表达。
- 能够回答验收问题的实验方法、规模与迭代节奏。

改变工具职责、固定选项的语义、四种排序信号的独立性、硬条件门槛或数学模型结构，应作为显式设计变更提出，不能以“实现细节”为名静默改变。

本规范不指定必须先修改哪个文件、不提供 P0/P1/M1 式施工顺序、不指定所有请求必须有几轮或每轮几条。**约束的是结果、意义和边界，路径由执行者用证据选择。**

## 附录 A：非约束性数值示例

以下仅解释模型行为，既不是永久默认值，也不是必须搜索的调参网格：

```text
τ = 1，λ = .5
u(3) = .25，u(4) = .6，u(5) = 1
D(none/mild/strong) = 1/.9/.75；unknown 中性并披露
ε = .1
偏好：match→1，partial→.5，no_match/unknown→0，去重后等权平均
示例关闭多样性修正
```

| 材料 | B | 档位 | D | p | 新 S | 旧倍率示例 S |
|---|---:|---:|---:|---:|---:|---:|
| 有用背景 | 1 | 3 | 1 | 0 | .3750 | 1.00 |
| 直接关键证据 | .5 | 5 | 1 | 0 | .6667 | .70 |
| 更低基础分关键证据 | .1 | 5 | 1 | 0 | .5455 | .14 |
| 受折扣的高价值材料 | 1 | 5 | .75 | 0 | .5625 | — |
| 符合偏好的中高价值材料 | 1 | 4 | 1 | 1 | .6500 | — |

因此，低 B 的关键材料可以翻身，4 档也可以超过 5 档。但不是无限逆转：同 D、同偏好时，B=100 的 3 档约 .62005，B=.01 的 5 档约 .50495，基础排序仍有作用。

旧稿的“首批 40／总计 80”“补读 2 页／5 秒”“schema4”等均为当时的候选方案，不是本规范的固定要求。实际预算和迁移版本根据实现证据、宿主边界及兼容需要决定。

数值稳定性可通过等价变换实现，例如 B≥τ 时用 `1/(1+τ/B)`，否则令 x=B/τ 后用 `x/(1+x)`；不要求采用这一具体分支写法。

## 附录 B：当前证据边界

此前已用临时脚本核算相同公式的 7 个数值例、10,000 组固定种子性质样本和极端浮点输入。它们支持公式与示例自洽，不是独立筛选原型已完成，也不是质量、漏收率或总成本收益已获验证。

真实默认参数、来源偏置映射、最合适的审查/补读预算及公开迁移时机仍需证据。不能把本文的数学严谨性、示例参数或工程测试通过等同于产品效果证明。

## 附录 C：实现现状（原型已落地的部分）

固定选项筛选原型已实现于 `lib/search/screening/`：`scoring.js`（公式与参数校验）、`policy.js`（固定选项与 sourceBiasPolicy 门槛）、`judgments.js`（Jev 固定选项请求/解码，含完整档位标准与实际检索来源）、`controller.js`（候选快照、准入、排序、有界补读）、`duplicates.js`（实验性近重复折叠）。对应测试 `scripts/test-screening.mjs`；当前 50 个隔离测试入口全部通过，未改动 fused/adaptive 默认行为与公开 schema。

消融回放已建立于 `scripts/screening-ablation-fixture.mjs`（3 个转录候选池，tool/gold 为开发参考标签，尚无可复核的独立盲评记录）与 `scripts/test-screening-ablation.mjs`（F→FH→FHV→新旧公式→单独 +D／+P→+D+P→折叠，救援为正交轴）。结论与边界一并记录，避免把机制验证当成效果证明：

- D 与 P 已拆分对照；本夹具中单个 +D 无排序效果，+P 仅在一个池改变顺序，二者均未获得独立增量证据。
- 折叠带来的首屏多样性提升（池 C distinct@5 2→5）在旧公式加折叠时同样成立，属折叠机制的作用，不归因于新公式；池 C 未折叠的 FHV 对照中新公式文档级 nDCG 为 .674、旧公式 .769；FHVDP 对照则两者均为 .674。不能混用两组比较。
- 所有准入材料的 tool 与 gold 价值一致，且无 tool-pass/gold-fail 样本：指标由 gold 价值字段计算，而重排也消费该字段，“新公式 ≥ 旧公式”主要是标签派生结果，不是独立质量证据。
- 折叠召回为样本内，且同簇跨 slug 镜像的漏折叠未测量；原型默认关闭折叠（`dedupe: false`），仅显式开启时生效。
- 参数为附录 A 示例值，未按真实 B 分布校准；消融脚本会打印其退化含义（当前 λ=.5 时任意一档价值差都压过全部已记录的基础分差）。

工程与契约层面本轮修复的缺陷：缺失来源信息不再生成非法单选项问题；补读文本作为新文本版本必须携带自己的安全检查结果，旧许可不继承，交付正文为新版本；作用域通过但信息状态为明确冲突时不再准入；档位问题携带完整分级标准、来源折扣判断携带真实 engines/engineRanks；`none/unknown` 必须中性且 `strong ≤ mild ≤ none`。

复审后的补充修复与验证：

- 信息状态增加 `established`。限制非空时，只有 scope 通过且 info 为 `established` 才准入；矛盾、缺失与明确冲突分别拒绝并披露。
- 原候选安全状态不为 `clear` 时不允许补读。`rescueScopeRecovered` 只计补读前条件未确立、补读后条件一致确立的状态转换；初始条件已通过的价值补读不计入；`rescueRecovered` 表示恢复全部准入资格的材料数（在数量截断与折叠前）；`rescueReadFailed` 单独记录失败读取。
- `runScreening` 支持顶层 intent 或 `question.intent`，两者冲突或方向缺失时在调用 judge 前报错，不静默丢失上下文。
- 补读轴调用实际 `runScreening`，读取和判断仍是离线模拟，输出尝试/失败/条件恢复/准入恢复及 judge 调用数，不声称测得真实网络、Jev 成本或质量收益。A3 的 403 不再产生确定档位，且其 scope 已通过，不进入条件补读。独立测试覆盖可补读候选读取失败、安全阻止、低档以及恢复后未入选的计数边界。
- 比较结论按指定对照组的实际数值生成，不再硬编码不等号。

本轮按审计分级落地的独立原型修复（未接入默认路径）：

- **快照合并**：按正文优先、文本更长优先、完整文本与元数据的稳定字典序打破并列，选择一个完整观察；snippet 或正文均携带该观察的版本、标题、日期等元数据，缺失值不借用其他观察。基础分与评分版本另行绑定。安全状态保守地取各来源行中最严格者（顺序无关），不因文本代表的选择而降低。
- **来源贡献**：`buildSnapshot({ engineWeights })` 只把正权重引擎计入 `engines/engineRanks`；零权重引擎不再扩大折扣适用范围。集成时必须传入解析后的路由权重，`provenanceBasis` 记录使用了哪种投影。
