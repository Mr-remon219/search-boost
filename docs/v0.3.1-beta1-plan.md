# SearchBoost 0.3.1-beta.1 实现方案与验收映射

状态：实现说明。不是 QA 放行，不是 npm 发布记录，也不是 live 验证。

基线：master `180961df8436358256fbf19262203cdd5154c559`（Release v0.3.0）。本分支不合并、不发布稳定版。

## 决策

0.3.0 的 `deepseek-search` 在代码里真实存在，不是只有文档。`lib/search/engines.js` 曾向 `POST https://api.deepseek.com/anthropic/v1/messages` 发送 `web_search_20250305`。同一引擎 ID 已进入池、Key、权重、MCP schema 和测试。

本版把这个 ID 的唯一协议换成官方 Search API `POST /v1/tools/search`。不新增第二个引擎，也不在失败时回到 messages/web_search。同一把 `DEEPSEEK_API_KEY` / 文件 Key 只发往这一条路径。

理由：官方指南把独立 Search API 和对话里的 web tools 分开；用模型回答冒充搜索会被拒绝。再造一个引擎 ID 会让同一 Key 有两条用户可见路径。保留旧路径作为回退同样会打两条协议。

启用后的默认路由仍遵守 0.3.0：已启用的 Key 进入省略 `engine_pool` 的默认搜索。没有新增第四个开关。

## 0.3.0 行为（不改）

- 省略 `engine_pool`：有已启用 API 就只用这些 API，否则用免 Key 池。
- `engine_pool` 和 `engines` 只作用于当次调用。显式 `engines` 可跨池，不能绕过缺 Key 或停用。
- API 失败不改走免费池。
- 保存 Key 不修改已有 `enabledEngines` 白名单。
- 没有白名单时，每把已配置的 Key 都算启用。因此在没有白名单时再保存一把 Key，会加入默认集合。这是原规则，测试会锁定，文案也会写明。它不是第二条协议。

## 四个包

1. `config keys --show`、轻量 TUI「默认搜索」、全屏「默认搜索」和 `status --json` 的 `defaultSearch` 说明：省略 `engine_pool` 时会用谁、谁可能产生费用、当次如何免 Key 或只用一家。没有已启用 API 时写明免 Key 池是完整配置。
2. `fused_search` 沿用 `engines`、`snippet`、`engineStats`、`warnings`。有官方 summary 时增加可选 `summary`，不写进 `snippet`。全部失败且 0 条才是工具错误（`fusedResultIsError`）。200 空结果是成功零条。一家失败但仍有结果不是整体错误。引擎失败类放在已有 `engineStats.*.note`。
3. `routeExplanation` 只描述实际选中的引擎。单引擎成功、空结果、失败都不调用其他引擎或旧协议。`runChain` 不再按顺序换引擎。
4. DeepSeek 只实现 Search。`need_content` 默认 false，不自动 Fetch，默认不发送 `localization`。query 按 Unicode 码点计 1–128，超长拒绝且不截断。count 只允许 1–50，缺省 10。仅 HTTP 408/429/5xx 额外重试最多 2 次；`Retry-After` 大于 1 秒则不再试。取消后不再请求。
